# 网维助手 · 临时数据 Demo（UI 0.1）

这是实际巡检项目的结果页面，不是项目说明网站。运行时只 GET 现有 FastAPI，页面不扫描网络，不写资产、不改调度配置、不连接团队进度服务。

> **2026-11-16 协作更新：** 后端已为 0.10.0，当前页面没有登录或 SSH UI。
> 新环境使用仓库根 `README.md` 的同源隔离构建和开发登录流程，不直接照搬旧端口与绝对路径。
> `generate:api` 和类型已经对齐 0.10.0，界面布局未改。

用户明确：正式前端后续重做，本页仅清晰展示API收到的数据，不承担项目讲解。
本轮最终版本为四个顶部分类、表格、选择/筛选和按需展开的原始JSON，已删除解释型侧栏、长篇引导和能力介绍。

## 本机打开

本轮已经生成 `<checkout-or-user-tool-path>`。
后端在启动时挂载该目录，无需再启动 Vite，也不需要 PHP。

在 PowerShell 中：

```powershell
Set-Location -LiteralPath "<checkout-or-user-tool-path>"
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-proxy-headers
```

浏览器打开 `http://127.0.0.1:8000/console/`。根地址 `/` 会跳到工作台。
若 8000 已有同一项目 API，无需启动第二个；若被其他程序占用，不要结束不明进程，可自行选其他本机端口。

本轮开发验收已启动一个 API 实例，不表示 API 已安装成后台自启服务。关掉该实例后网页和 API 会断开；
已有 `NetAssistant-Discovery` 扫描服务与它独立，页面关闭不等于扫描服务停止。

## 四块内容

1. **资产台账**：名称、稳定 UUID、登记来源、管理分类、关联判断；点击名称查看观测历史及审计。
2. **扫描批次**：按开始时间倒序选择，查看当次目标/排除范围、状态、覆盖、发现快照、自动关联依据。
3. **探测证据**：选择批次，按 IP/方法/结果筛选，查看耗时、时间、原因码和原始 JSON，50 条分页。
4. **每日调度**：配置时刻、下一到期、心跳、数据库读取状态、每日尝试历史和对应扫描。

本页不计为正式管理界面任务完成。开发助手应用户要求更新说明站勾选，是独立人工操作，不是本Demo的功能。

首批两个档案如实显示人工登记，后续程序自动关联不改写它们的登记来源。
MAC 关联不是身份认证；档案的管理分类不等于采集授权。
观测历史中的 IP 只属于标示时间，不是“当前在线 IP”。
CPU、内存、进程显示“未采集”，没有 0% 假指标。

## 刷新与错误语义

- “刷新数据”重新读取已有结果，不发网络探测、不新建扫描批次。
- 页面不自动轮询。各区显示自己的读取时间，超过一分钟提示可能过期；该阈值仅是页面资料新鲜度提醒，不是设备离线判据。
- 刷新失败时显示错误码/请求编号，并标记保留的是旧资料；第一次失败不显示成零资产或零故障。
- 初始目录顺着游标读取，最多20页、每页200条；未读完明确标注不是全量。任务从已载入目录中按时间倒序展示。
- 证据分页按服务端记录顺序；下一页按钮仅在有游标时可用。
- 各接口独立读取，不是数据库同一时刻的原子快照。
- 未知状态不会默认显示正常。HTML 等响应内容只按文本展示。
- 请求15秒超时；切换对象会取消旧请求，并防止晚到响应覆盖新对象。

## 重新安装与构建

需要本机 Node.js 与 npm；本轮环境 Node 24.11.0、npm 11.6.1。
依赖由 `package-lock.json` 锁定。运行预构建静态文件时不需要 Node，仍然需要 Python API。

```powershell
Set-Location -LiteralPath "<checkout-or-user-tool-path>"
npm.cmd ci
npm.cmd run generate:api
npm.cmd test
npm.cmd run build
```

`generate:api` 从当前 `backend/docs/openapi-0.5.0.json` 生成 `src/api-schema.d.ts`。
后端契约更新时先更新 OpenAPI，再生成类型并检查前端，不能直接修改生成文件。
如果 API 启动时还没有构建目录，会返回503“前端尚未构建”；首次构建完成后需重启 API。
不要删除正在提供服务的构建目录来更新线上文件；本轮没有操作线上部署。

开发时先启动后端，再在前端运行 `npm.cmd run dev`，打开 `http://127.0.0.1:5182/console/`。
Vite 仅绑定本机，代理 `/api` 到本机8000，不需要放宽 CORS。

## 部署边界

- 网页静态产物：`frontend\dist`；巡检服务：FastAPI；巡检持久化：`backend\data\inspection.sqlite`。
- 独立的项目说明站与 `/api/progress` 数据库不是本工作台的数据源，不能混装或覆盖。
- 仅把 dist 放进宝塔 PHP/静态目录不会得到巡检 API；本轮只交付本机运行方式，没有改宝塔配置。
- 当前无登录和安全写API，只监听127.0.0.1。不要把8000暴露公网，也不要为了手机访问改成0.0.0.0。
- 远程服务器自身的127.0.0.1、管理电脑的127.0.0.1、容器的127.0.0.1各指向自身，不能混用。
  外部宝塔服务器不会因此自动访问管理电脑上的 VMware NAT 网段。
- 跨机器访问、鉴权与部署需要单独设计，本轮不新增反向代理、端口映射或远程扫描。
