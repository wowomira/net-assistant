# 任务03：稳定资产台账与发现关联

日期：2026-11-15。用户已批准：稳定编号、发现关联、地址历史、防止换 IP/同 IP 换设备误合并；
保持人工确认，不延伸 Agent/授权采集/前端。沿用当前工程，无 Git 仓库，不创建虚假提交记录。

## 设计选择

拒绝以 IP 为主键，也不凭 MAC 自动合并。采用独立 UUID 台账 + 人工确认关联 + 可撤回关联审计。
现有 discovery_* 记录保持原样，历史快照里的分类不改写；新增 API 字段表达当前台账关联。

新增三张表：
- assets：稳定 UUID、来源逻辑范围 scope_id、名称、类型、负责人备注、revision、创建/更新时间。
- asset_discovery_links：一条发现记录最多有一个当前确认关联；一个资产可有多条发现/多个地址。
- asset_audit_events：登记、关联、撤回与元信息修改的原因、local_cli 来源、时间、资产版本和发现引用。

当前用 discovery scope_id 作为保守的逻辑网络隔离边界，不声称它是物理网络自动识别结果。
跨 scope 自动关联/人工合并不在本轮；网络环境切换时不能复用旧范围身份而不核对。
IP 不唯一；没有全局 MAC 唯一约束。建议只参考同 scope 有效 MAC 对应的已确认历史，
名称/IP 相同不产生身份结论；建议列表有上限与截断标志，永不写库。
缺少证据、多个匹配、同地址不同 MAC 等明确显示待人工核对；MAC 相同也不授予权限。

写操作仅本机 CLI，不新增无鉴权 HTTP 写接口。复用扫描文件锁，并用 BEGIN IMMEDIATE、
唯一约束和 revision 阻止并发/过期覆盖。每次人工修改必须给原因；local_cli 是操作入口标记，
不是已认证的人类用户。重复关联同一资产为幂等；改关联必须先撤回，并保留审计。
仅允许 completed/partial 任务的 direct_response 发现登记/关联；候选/运行中/失败任务不直接确认为资产。
关联时显式检查 scope，一切关联都不触发探测、不扩展授权范围、不修改主机采集权限。

只读 API：资产列表/详情、已确认发现与地址观测历史、审计、单条发现关联与建议。
资产不设“当前 IP”或“在线”假结论；历史地址返回 observedAt、jobId、scopeId，
前端使用稳定资产 id。现有 hosts 增加 assetId/associationStatus，保留原快照字段语义。
元信息可通过带 expected_revision 的 CLI 更新；不实现资产删除/合并。

迁移：0002_asset_registry 增量建表，不重建原始探测表；非空旧库升级前自动做 SQLite 一致性备份，
验证备份 integrity/FK。版本已最新不重复备份。只有 CLI 使用写入口，API 不执行迁移。

## 不在本轮

当前在线结论、后台调度、防抖事件、业务前端、线上部署、共享勾选修改。
