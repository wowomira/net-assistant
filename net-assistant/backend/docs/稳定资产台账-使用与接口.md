# 稳定资产台账：使用与接口

版本：后端0.4.0，2026-11-15。采集授权/Agent不在本轮。
自动登记与每日扫描完整说明见《自动资产与每日扫描-使用说明》。

## 1. 三类编号不要混用

- `assetId` / 资产详情的 `id`：稳定 UUID，代表台账中的一台设备；不是密码或认证凭据。
- `discoveryHostId` / 发现接口的 `id`：某次扫描在某个地址的发现快照。
- `jobId`：一次扫描任务；同一设备可以关联多次扫描中的多条发现。

```text
稳定资产 UUID
  ├── 确认关联 → 扫描1中的发现 → 地址A、MAC、观测时间、探测证据
  └── 确认关联 → 扫描2中的发现 → 地址B、MAC、观测时间、探测证据
```

资产姓名、类型、负责人、备注可改；改元信息不更换 UUID。
IP 不设全局唯一约束，不凭 IP 继承资产历史或采集权限。
发现快照不回写成“已纳管”，当前关联另用 assetId/associationStatus 表达。
人工档案managed、自动发现档案discovered；都不证明所有权、当前在线、操作系统或采集授权。

## 2. 已实现的识别与确认规则

1. 仅 completed/partial 任务中的 direct_response 发现可以登记/关联。
   ARP 缓存候选、运行中、失败、中断记录不能直接确认为资产。
2. 已确认的同逻辑 scope 历史 MAC 可以给出建议；统一大小写/冒号与连字符，
   忽略无效、全零、组播/广播 MAC。
3. IP 或名称相同不构成身份匹配。相同地址有不同/未知 MAC 的历史关联时给出风险提示。
4. 重复 MAC 可以对应多个独立资产，建议标 ambiguous。最多20项，超出明确标 truncated。
5. suggest/GET建议只读，不写关联；扫描末尾另外运行自动策略：
   同scope有效MAC历史唯一且本任务无重复时自动关联；未知/冲突则新建needs_review档案。
   自动决定写asset_identity_decisions与审计，actor=automatic_discovery，不是设备认证。
6. 单条发现最多关联一个资产。一个资产允许多地址/多网卡，不设置虚假的单一“当前IP”。
7. 同一关联重试不增加重复记录、不递增版本、不覆盖原确认原因。
8. 错误关联必须先 unlink，再 link 到正确资产。撤回只删除当前关联，不删除发现或审计。
   被撤回的证据不再用于当前匹配建议。
9. 当前逻辑网络边界采用 discovery scope_id，不是自动识别的物理网络身份。
   本轮禁止跨 scope 关联；跨网络迁移/人工合并以后单独设计。
10. 任何关联都不发包、不扩大目标允许范围、不修改 CPU/内存/进程采集权限。

换 IP 验证已在独立测试库完成；没有为测试更改真实虚拟机网络。
纯网络线索无法在证据不足时自动证明身份，本轮明确保留人工核对。

## 4. 本机 CLI

在 `<checkout-or-user-tool-path>` 执行。
CLI JSON 用 snake_case，HTTP JSON 用 camelCase；不要把命令行输出当 HTTP 契约。
所有命令都不触发扫描。可在子命令前用 `--database` 指定绝对路径；
否则用 INSPECT_DB 或工程 data/inspection.sqlite。

只读查看：

```text
.\.venv\Scripts\python.exe -m app.assets.cli list
.\.venv\Scripts\python.exe -m app.assets.cli show --asset-id 00000000-0000-4000-8000-000000000001
.\.venv\Scripts\python.exe -m app.assets.cli observations --asset-id 00000000-0000-4000-8000-000000000001
.\.venv\Scripts\python.exe -m app.assets.cli audit --asset-id 00000000-0000-4000-8000-000000000001
.\.venv\Scripts\python.exe -m app.assets.cli suggest --host-id 00000000-0000-4000-8000-000000000001
```

以下是操作模板，尖括号必须换成真实值，不能原样复制；当前两台已登记，无需重复 register：

```text
python -m app.assets.cli register --host-id <发现ID> --name <管理名称> --kind virtual_machine --reason <登记依据>
python -m app.assets.cli link --asset-id <资产ID> --host-id <新发现ID> --expected-revision <最新版本> --reason <核对依据>
python -m app.assets.cli unlink --asset-id <资产ID> --host-id <误关联发现ID> --expected-revision <最新版本> --reason <撤回原因>
python -m app.assets.cli update --asset-id <资产ID> --expected-revision <最新版本> --name <新名称> --reason <修改原因>
```

上面的 python 必须使用项目 `.venv\Scripts\python.exe`，不是全局环境。
名称、原因及备注等包含空格时加引号。
类型：unknown/server/workstation/virtual_machine/network_device/other。
可选 `--owner`、`--notes`；update 支持 `--clear-owner`，与 --owner 互斥。
不支持改 scope/id/采集权限；不支持删除或合并资产。

写入和扫描共用OS文件锁；revision 防止读取旧版本后覆盖别人的操作。
先 show 最新详情，再填写 expected_revision，不要硬编码版本。
本地 CLI 成功返回0，业务/校验/存储错误返回2并向 stderr 输出结构化 code/message。

| 错误码 | 含义 |
|---|---|
| asset_not_found / discovery_host_not_found | 对象不存在 |
| observation_not_confirmable | 当前发现证据或任务状态不满足确认条件 |
| observation_already_linked | 不得重复登记或直接改关联 |
| observation_not_linked | 不存在待撤回的关联 |
| scope_mismatch | 跨逻辑范围，当前不支持 |
| revision_conflict | 资产版本已变化，重新读取 |
| validation_error / invalid_asset_update | 字段、原因、类型或修改内容不合法 |
| storage_or_writer_busy | 存储不可访问或已有写入者 |
| database_unavailable | 数据库缺失、不可用或尚未升级 |

local_cli 只记录操作入口，不是经过登录认证的人员身份；本轮未实现账号系统。
Windows 批量脚本保存为 UTF-8 文件执行，避免将中文源码通过旧编码 PowerShell 管道送给 python -。

## 5. 前端用的只读接口

| 路径 | 作用 |
|---|---|
| GET /api/v1/assets | 稳定台账分页 |
| GET /api/v1/assets/{asset_id} | 名称/类型/版本、关联数和最后观测时间 |
| GET /api/v1/assets/{asset_id}/observations | 当前确认关联中的发现及地址观测历史 |
| GET /api/v1/assets/{asset_id}/audit | 所有登记/关联/撤回/元信息修改审计 |
| GET /api/v1/discovery-hosts/{host_id}/asset-association | 当前关联及待确认建议 |

分页 limit默认50、最多200，nextCursor 为 null 表示结束。顺序为登记/确认/事件序号升序，
不是 observedAt 时间排序；补关联较早发现不改变它的观测时间。
资产 lastObservedAt 取当前有效关联中的最大观测时间，不取确认时间；
所有关联撤回后为 null。被撤回的关联不在当前 observations 列表，但审计仍可追溯。

资产示意（字段含义示例，不是另外一台真实设备）：

```json
{
  "id": "稳定资产UUID",
  "scopeId": "逻辑范围UUID",
  "name": "管理名称",
  "assetKind": "virtual_machine",
  "owner": null,
  "notes": "",
  "revision": 2,
  "createdAt": "2026-11-15T00:00:00.000Z",
  "updatedAt": "2026-11-15T00:10:00.000Z",
  "managementStatus": "managed",
  "collectionAccess": "not_enrolled",
  "hostMetrics": null,
  "hostMetricsStatus": "not_collected",
  "linkedObservationCount": 2,
  "lastObservedAt": "2026-11-15T00:05:00.000Z"
}
```

原发现列表新增 assetId（无关联为null）、associationStatus；其余旧快照字段语义不变。
前端不要以 IP 建设备详情路由，不把 UUID 当认证凭据，不把历史观测画成实时健康状态。
API 只读、禁缓存；不提供 POST/PATCH/DELETE，未知对象404，缺库/旧库未升级等503。
新增registrationSource/identityStatus/identityVerified以及automaticDecision；
actor允许local_cli/automatic_discovery。模型见 `docs/openapi-0.4.0.json`，旧版保留，尚未生成TypeScript客户端。
只监听127.0.0.1，暂无完整鉴权，不应改为公网/实验网开放。

## 6. 存储与升级

仍用原独立巡检库，不是新建第二个巡检数据库：

```text
<checkout-or-user-tool-path>
```

迁移 `0002_asset_registry` 在四张原发现表上增加：

- assets：台账及版本。
- asset_discovery_links：当前确认关联，发现 ID 唯一。
- asset_audit_events：操作审计，原始发现不删除。

旧版独立巡检库升级：`.\.venv\Scripts\python.exe -m app.assets.cli migrate`。
旧库升级前自动生成 `data/backups/inspection.pre-migration.*.sqlite` 并检查完整性/外键。
备份失败不迁移，迁移显式事务失败回滚表结构与版本号；已最新不重复做迁移备份。
迁移、登记等写入先拿共享写入锁；API 不做自动迁移。

备份恢复读取试验只在临时目录，不覆盖工作库。此机制不是每日备份/轮换/完整灾备方案。
本轮交付另外做了包含新台账的 post-task03 快照，并验证恢复；路径见《任务03-资产台账验收》。
pre-migration 是迁移前版本，post-task03 是本轮完成后版本，不要混淆。
不要把运行中的 SQLite 直接上传宝塔，不要通过共享目录跨机器打开工作库。
原始审计不会因纠错消失，但本地库不提供抵御本机管理员篡改的密码学防篡改保证。
