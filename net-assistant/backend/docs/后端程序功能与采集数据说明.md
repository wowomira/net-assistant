## 一、一句话理解当前程序

**它现在是管理电脑上运行的“有限网络发现 + 常用 TCP 端口检查 + 证据留档 + 资产关联 + 每日扫描”程序，还不是完整的服务器监控、网站监测或故障处置系统。**

可以把它理解成一个从设备外面观察的检查员：

- 在你配置的范围内寻找有响应的地址；
- 检查发现候选上的一组 TCP 端口能否建立连接；
- 条件满足时补充有限的 HTTP 响应头、TLS 验证和服务横幅；
- 保存实际结果与时间；
- 自动建立发现档案，或保守地关联已有档案；
- 由独立后台工作进程每天触发一次，同时保留手动入口；
- 通过只读接口和简单页面提供已有结果。

它**不会登录被检查设备**，也没有进入远程主机内部读取 CPU、内存、进程。

| 概念 | 大白话解释 | 当前情况 |
|---|---|---|
| 网络发现 | 观察哪些地址在检查时给过响应 | 已实现，有真实实验网记录 |
| 资产档案 | 建立相对稳定的管理编号，关联多次发现 | 已实现，关联规则有局限 |
| 主机内部采集 | 获取 CPU、内存、进程等内部指标 | 未实现 |

**发现设备 ≠ 证明它属于你；进入台账 ≠ 授权主机采集；有 UUID ≠ 完成设备身份认证。**

## 二、程序组成与运行链路

```text
人工维护范围与每日计划
         │
         ├── 手动扫描命令
         │
Windows 服务 → 调度工作进程 → 到期入口
         │                    │
         └─────────┬──────────┘
                   ↓
              共用扫描写锁
                   ↓
        范围与源网卡校验 / 执行器
                   ↓
          ICMP / ARP / TCP 探测
                   ↓
     条件满足时 HTTP / TLS / 横幅取证
                   ↓
         保存发现快照和原始证据
                   ↓
          自动建档 / 保守关联
                   ↓
        SQLite + Markdown / JSON 报告
                   │
          只读 FastAPI 接口
                   ↓
          已有简单数据 Demo
```

另有独立链路：**调度工作进程写心跳文件，API 读取心跳和自动执行历史。** 心跳不是目标设备在线状态。

| 运行对象 | 负责什么 | 不能据此证明什么 |
|---|---|---|
| API 进程 | 响应页面和数据请求 | 自动扫描成功、设备健康 |
| Windows 服务 | 托管调度工作进程 | 本轮未重新核验实时系统服务状态 |
| 调度工作进程 | 判断到期、写心跳、管理子进程 | 所有扫描都成功 |
| 扫描任务 | 执行一次配置内检查 | 设备此后一直在线 |

API 仍是独立手动启动的进程。**关闭临时 API 不等于关闭每日扫描；每日扫描有服务托管，也不等于 API 已开机自启。**

## 三、一次扫描怎么运行

### 第 1 步：读取并校验配置

配置指定：

- 逻辑范围名称；
- IPv4 单地址、CIDR 网段或起止地址范围，以及排除项；
- 发包使用的本机源 IPv4；
- 完整 TCP 清单与发现补充端口；
- 允许取 HTTP / HTTPS / TLS / 横幅证据的端口子集；
- 超时、并发、总时间预算、地址数量上限；
- ICMP / ARP 开关；
- 可选的本机 VMware 配置文件提示。

实验配置为 `192.0.2.192/24`，排除 `.1`、`.2`、`.254`，展开得到 **251 个候选地址**。地址来自配置，不是算法写死。

公网默认不允许，回环目标也需显式配置。**允许某类地址的配置开关不等于已经取得扫描授权。**

### 第 2 步：发现候选设备

对每个配置地址：

1. 按开关执行 ICMP、ARP；
2. 没有直接响应时，尝试配置的少量 TCP 发现端口；
3. 保存成功、超时、拒绝、错误等探测记录；
4. 有符合条件的证据才生成发现候选。

当前规则中：

- 有效 ICMP 回包或 TCP 连接成功可形成 `direct_response`；
- 只有 ARP 解析或 TCP 明确拒绝时为 `candidate_only`；
- 仅有这些候选线索不会立即自动建档。

不回 ping 不会直接跳过 TCP 发现。**但所有发现方式都没形成候选时，后续也不会对该地址执行整组端口检查。**

### 第 3 步：对候选检查配置中的完整 TCP 清单

本实验清单为 **115 个常用 TCP 端口**，不是全部 65535 个 TCP 端口，也不是 UDP。

2 个候选对应 `2 × 115 = 230` 次这一阶段检查。发现阶段也有少量 TCP 尝试，通过 `phase` 区分，不能只按总数误认覆盖范围。

候选若在此阶段出现 TCP 连接成功，会提升为直接响应，随后可参与自动资产处理。

### 第 4 步：按配置补充服务证据

必须同时满足：

1. 端口已连接成功；
2. 命中 HTTP / HTTPS / TLS / banner 对应配置子集。

才执行对应取证。所以“支持 HTTP 取证”和“工作库已经有真实 HTTP 结果”是两回事。

### 第 5 步：留档、关联与导出

原始结果先保存，`completed / partial` 任务再执行自动建档/关联。

若资产处理失败，发现记录仍保留，任务标 `partial`，原因记录为 `asset_registration_failed`，不会掩盖失败。

正常执行链路结束后生成 Markdown 与 JSON 报告。导出本身也可能失败，**数据库有记录不保证报告文件一定成功生成**。

## 四、每种方式到底收集什么

### 4.1 ICMP：目标是否回应 ping 类请求

| 项目 | 当前行为 |
|---|---|
| 方法 | Windows 原生 ICMP API，不解析命令行 ping 文案 |
| 采集 | 回复地址、IP 状态、往返时延、耗时、观测时间、失败原因码 |
| 状态 | `reply / timeout / no_response / error / not_supported` |
| 有效回包说明 | 检查时得到该目标有效回应 |
| 不回包不能说明 | 不能直接认定关机、断网或不存在 |

`roundTripMs` 是 ICMP 的往返时延；通用 `durationMs` 是探测代码耗时。**不能把所有方法的 durationMs 都叫 ping 延迟。**

### 4.2 ARP：同链路地址解析与 MAC 线索

| 项目 | 当前行为 |
|---|---|
| 方法 | Windows `SendARP` |
| 适用 | 已验证源网卡所在本地链路 |
| 采集 | MAC、来源、缓存可能性、耗时、失败码 |
| 状态 | `resolved / no_response / error / not_applicable` |
| 用途 | 辅助发现，提供 MAC 关联线索 |
| 局限 | 可能使用缓存，不能单独证明当前在线或设备身份 |

跨路由目标不具备本实现的同链路 ARP 适用条件。**无 MAC 是允许的实际结果，不能由页面编造。**

### 4.3 TCP：端口能否建立连接

| 状态 | 当前含义 | 不应解释成 |
|---|---|---|
| `open` | 此次连接成功 | 已确认服务名、版本、漏洞、业务健康 |
| `refused` | 明确连接拒绝 | 整台设备离线 |
| `timeout` | 配置时间内未连接成功 | 确认端口关闭或设备不存在 |
| `unreachable` | 套接字返回网络/主机不可达类错误 | 已定位具体网络故障根因 |
| `error` | 其他连接/执行错误 | 已确定目标业务故障原因 |

例如 445 可连接，只能直接证明当时能连接这个端口，**不能凭端口习惯宣布完成 Windows 或 SMB 版本识别**。

### 4.4 HTTP / HTTPS：只请求根路径响应头

当前行为：

- 访问 `http(s)://目标IP:端口/`，方法 **HEAD**；
- 不跟随跳转，不下载保存正文；
- 不带个人浏览器登录状态；
- 不保存 Cookie 和认证头；
- 不登录，不做口令或漏洞测试。

| 保存字段 | 说明 |
|---|---|
| `scheme / path / requestMethod` | http(s)、`/`、HEAD |
| `statusCode` | 实际 HTTP 状态码 |
| `headers` | 只选 `server / content-type / content-length / allow`，并限长 |
| `followedRedirect` | false |
| `bodyCollected` | false |

**不采集网页标题、HTML 正文、截图、favicon、页面资源和登录后内容。**

收到 404 / 500 也可能标 HTTP `response`，只代表收到 HTTP 响应，**不代表网站正常**。业务期望状态码和网站健康规则尚未实现。

URL 基于 IP 和根路径，还不是完整的域名 / SNI / 虚拟主机 / 自定义路径监测配置。得到默认站点响应不能代表检查了所有网站。

### 4.5 TLS：握手、严格验证和证书字段

验证成功时保存：

- TLS 版本和加密套件；
- subject / issuer；
- `notBefore / notAfter`；
- `subjectAltName`；
- 验证通过标识。

证书不可信、名称不匹配等保留 `certificate_error / tls_verification_failed`，不会关闭验证再假报正常。

当前以 IP 作为 `server_hostname`；证书只有域名、没有该 IP 时可能失败，**不能因此笼统说网站一定不可用**。

验证失败时不保证拿到完整证书详情。证书有效期字段可保存，**到期阈值告警、变更监测与网站周期监测未完成**。

### 4.6 服务横幅：只读服务主动发来的有限文字

- 建立 TCP 连接，最多读 **512 字节**；
- 不发应用层命令；
- 清理和限长；
- 保存 `received / empty / timeout / error`。

软件标识只是服务提供的文字，不保证真实版本。许多服务要等客户端先发命令才响应，横幅空或超时不能直接判故障。

### 4.7 本机 VMware 上下文：不是网络操作系统指纹

读取**管理电脑上人工配置的 `.vmx` 文件**，按 MAC 匹配：

- `displayName`：配置名称；
- `guestOS`：配置系统提示；
- 虚拟网卡 MAC；
- 文件路径、`sourceType=local_vmware_configuration` 等来源说明。

**不是远程登录，不是运行中的 CPU / 内存，也不是网络扫描认出了实际系统。**

配置可能过时，与运行系统不一致。换电脑路径可能失效，也可以不提供这类上下文。当前上下文包含本机路径，分享原始结果前应检查隐私。

## 五、数据字段怎么理解

### 5.1 原始探测记录

| API 字段 | 含义 |
|---|---|
| `id / jobId` | 探测编号 / 所属扫描编号 |
| `address` | 目标 IPv4 |
| `phase` | `discovery / inventory / enrichment`，分别为发现、端口清单、补充取证 |
| `method` | `icmp / arp / tcp / http / tls / banner` |
| `port` | 不适用时为 null |
| `status` | 具体方法的执行结果 |
| `durationMs` | 探测耗时，毫秒 |
| `reasonCode` | 有时提供的失败/限制原因 |
| `evidence` | 方法相关证据 |
| `observedAt` | 该次结果记录的时间 |

单条 `evidence` 序列化后限制为 **2 KiB**，超过保存截断标记和有限预览，不保证完整。

数据库字段多为 snake_case，HTTP API 主要转 camelCase。原始 JSON 报告保留存储读取结构，不能假定与 HTTP 响应逐键相同。

### 5.2 发现快照

保存某地址在某次任务中的 MAC、发现方法、直接响应/候选、本机提示、观测时间、原始分类。

查询可返回该轮 `openPorts` 和当前 `assetId / associationStatus`。

**快照 ID、IP 都不是永久资产 ID。** 同一设备三轮有三条快照，不是三台设备。

快照保留原始分类，登记台账不回写全部历史。所以发现接口 `managementStatus=discovered` 与台账接口 `managed` 可以同时成立，它们描述不同层次。

### 5.3 缺失主机指标

当前接口明确返回：

```json
{
  "hostMetrics": null,
  "hostMetricsStatus": "not_collected",
  "collectionAccess": "not_enrolled"
}
```

表示未采集，不是 CPU 0%、内存 0、进程 0。模型中的预留状态也不能证明已有相应授权流程。

### 5.4 时间必须区分

- `observedAt`：观测时间；
- `startedAt / finishedAt`：任务起止；
- `confirmedAt`：建立关联时间；
- `createdAt / updatedAt`：档案创建/修改时间；
- `heartbeatAt`：工作进程报告时间；
- `checkedAt`：状态响应读取/生成时间。

**刷新不会让早上扫描结果变成下午刚检查。** 原始业务时间通常以 UTC `Z` 保存，本文转北京时间说明。

## 六、资产档案与原设备判断规则

### 6.1 档案是什么

保存稳定 UUID、逻辑范围、名称、类型、负责人、备注、revision、创建/更新时间、登记来源和身份判断状态。

关联表把多次快照接到档案，审计表保存登记、关联、撤回、修改的来源和理由。

**IP 不是 assets 表里被不断覆盖的永久身份字段。** 历史地址在关联的发现记录中保留。

### 6.2 自动规则

| 条件 | 动作 / 规则 |
|---|---|
| 该发现已有自动处理决定 | 不重复处理，防止重放覆盖人工纠错 |
| 已有显式关联 | 保留，`preserve_explicit_link` |
| 不是直接响应 | 跳过自动建档，`no_direct_response` |
| 无有效 MAC | 新建独立待核验档案，`missing_or_invalid_mac` |
| 同次扫描 MAC 重复 | 不自动合并，独立待核验，`duplicate_mac_in_scan` |
| 同范围历史 MAC 指向多个资产 | 不合并，独立待核验，`ambiguous_mac_history` |
| 同范围有效 MAC 只对应一个历史资产且本轮不重复 | 关联原 UUID，`unique_mac_same_scope` |
| MAC 有效且无历史对应 | 新建，`new_mac` |

有效 MAC 校验包括格式、非全零、非组播，并统一大小写和分隔符。**有效也不等于不可伪造的凭据。**

自动新建名称为“发现设备 + IP”，类型 `unknown`、负责人 null，不自动猜“你的服务器”或虚拟机名称。

### 6.3 实际场景

| 场景 | 当前处理 |
|---|---|
| 同范围、MAC 唯一，IP 变化 | 可沿用编号，保存不同地址观测 |
| 同 IP 后来换 MAC | 不凭 IP 合并 |
| 无 MAC，重复扫描 | 缺少可靠归一依据，可能多次产生待核验档案 |
| 虚拟机克隆造成重复 MAC | 不能保证自动认清，按冲突规则处理 |
| 跨逻辑范围 | 不自动沿用，本轮显式关联也拒绝跨范围 |
| 人工撤回后重放同一任务 | 已有决定防止自动挂回 |

`scopeId` 来自配置的逻辑范围；同名配置可能继续沿用 scope。**它不是自动识别的物理网络身份。** 换网络应重新核对范围与命名。

### 6.4 来源和状态

| 字段 / 值 | 含义 |
|---|---|
| `registrationSource=manual` | 首次档案由本机人工入口登记 |
| `registrationSource=automatic` | 首次档案由扫描自动创建 |
| `identityStatus=manual_confirmed` | 人工管理确认，不是加密认证 |
| `observed_mac` | 新 MAC 首次自动建档 |
| `mac_correlated` | 自动来源档案按 MAC 历史关联 |
| `needs_review` | 缺失、重复或歧义待核验 |
| `identityVerified=false` | 尚无可信设备认证 |
| `actor=local_cli` | 本机命令行操作，不是实名账号 |
| `actor=automatic_discovery` | 扫描自动处理 |

人工档案后续自动关联仍保留 `manual` 来源和原分类，不能改说成自动新建。

当前台账按登记来源派生 `managed / discovered`；还不是可独立审批、升级状态的完整纳管流程。

## 七、每日自动扫描与手动扫描

### 7.1 当前计划

- 名称 `vmnet8-daily`；
- **每天北京时间 09:00**；
- 固定偏移 `480` 分钟，不依赖系统当前时区；
- 独立 Windows 服务适配已有安装和真实运行证据；
- 本轮未重新安装、启停或重启服务。

工作进程约每 **30 秒**判断到期、约每 **2 秒**写心跳。**不是每 30 秒重扫网络。**

### 7.2 每日一次的准确含义

同计划名、同本地日期最多一次正式自动尝试：

- 未到期不扫；
- 已到期且未尝试则执行；
- 扫描锁忙不占名额，后续再判断；
- `completed / partial / failed / interrupted` 都算已尝试；
- 同日重复调用不追加自动扫描；
- 停机恢复只考虑当天，不补过去每天积压。

这是**每日最多一次正式尝试**，不是保证每天成功一次。分钟级逐设备监测、无限失败重试、告警防抖和恢复规则未实现。

### 7.3 手动入口

手动扫描共用执行器和写锁，**不占每日名额**。同一天可以有一轮自动、若干轮手动。

手动不会自动取消当天计划，自动也不会禁用手动入口。

### 7.4 心跳与结果分开看

- `worker.state`：工作进程心跳；
- `todayRun / latestRun`：自动执行记录；
- `todayStatus`：当天计划读取结果；
- `database.state`：读取/schema 是否可用，不证明可写；
- `lastInvocation=already_attempted`：名额已使用，不证明那次成功。

心跳超过 **90 秒**可显示 stale；缺失、损坏、配置指纹不符等为 unknown。API 不通过实时 SCM 查询保证服务活着。

状态读取不扫描，也不修复遗留 running。恢复发生在后续取得扫描锁的执行入口。
