## 1. 项目现在能够完成

| 能力 | 谁执行 | 真实边界 |
|---|---|---|
| 按配置校验并扫描授权 IPv4 地址/范围 | 发现 CLI 或每日工作进程 | 未做 UDP/IPv6/全端口/漏洞利用；常用 TCP 清单为可配置 115 项 |
| 保存 ICMP、ARP、TCP 与按条件产生的服务证据 | 探测适配器、执行器、SQLite | ARP 可有缓存；超时不等于关闭，完成不等于设备健康 |
| 扫描后自动建档、关联发现、记录决策与审计 | automatic_discovery 规则 | 需直接响应；MAC 是保守线索，不是可信身份 |
| 相同逻辑范围、唯一有效 MAC 的后续发现沿用资产 UUID | 自动关联规则 | 无 MAC/重复/歧义会建待核验档案；真实换 IP 尚未实测 |
| Windows 后台每日到期检查并执行一次 | Windows 服务 + 项目 worker + 每日数据库名额 | 服务无需个人用户登录；不保证关机或断网时获得数据 |
| 避免每日自动重复、避免与手动扫描同时写入 | SQLite 唯一约束 + OS 文件锁 | 失败也计当天尝试；手动不占每日名额；当前不排队执行忙任务 |
| 进程异常后的有限拉起与已接管子进程清理 | 系统服务恢复策略 + Windows Job Object | 系统托管能力，不是 AI 回来帮忙；不等于硬件故障自愈 |
| 读取台账、发现、探测、身份决策、每日记录和心跳 | 只读 FastAPI | 无鉴权写接口；API 本轮没有安装常驻/自启托管 |
| 告诉前端“未知、过期、失败、未到期” | 有类型的状态接口 | 心跳与扫描结果分开；未知不能显示绿灯 |
| 手动建档、修改和关联纠错 | 本地资产 CLI | 人工管理入口，不是自动识别所有权/授权 |

## 2. 本次由 AI 执行，但不能说成项目会自动完成的事

| 我执行的动作 | 项目当前不会自行做什么 |
|---|---|
| 编写代码、测试和文档 | 运行中的项目不会自行开发后续功能或修复自己的代码 |
| 选定授权 `.141` 作为单地址验收目标 | 项目不会自行获得新范围授权，也没有自动挑选学校目标的功能 |
| 创建独立验收计划并设 00:00 以立即到期 | 不是正式 09:00 已自然触发；正式时间未改 |
| 调用安装脚本，授权服务目录、启动并切换旧任务 | 安装器可再次执行，但程序不会未经操作员安装系统服务、申请管理员或替你换机 |
| 强制结束独立服务验证系统恢复 | 项目不会为了证明自己而随机结束进程；运行能力是异常发生后的既定托管恢复 |
| 启动临时 API、请求接口、关闭临时进程 | 是开发验收；任务07另有真实数据Demo，但不是正式业务前端完成，也不是API永久自启 |
| 比较工作库各表行数和指纹 | 是本轮验收操作，不是自动数据完整性巡检/每日备份功能 |
| 在测试库构造失败/过期/重复身份记录 | 只是自动化测试证据，不是实验虚拟机真实发生过这些情况 |
| 阅读结果并解释含义 | 当前没有生成这种中文分析报告的运行时 AI 模块 |

早先两台工作库资产由我调用人工 CLI 登记，来源仍是 `manual`，不会改写为自动成果。后续真实扫描已经由项目自动追加关联；本轮另从独立空库、无 VMX 上下文验证了 `registration_source=automatic` 新档案生成，不把该验证档案导入工作库。
