# 任务04：自动资产档案与每日扫描

日期：2026-11-15（Asia/Shanghai）。用户明确要求本轮直接实施并在完成后汇报。

## 设计约定

1. 扫描末尾自动处理 completed/partial 任务中的 direct_response 发现。
   新设备建 UUID 档案；同 scope、有效单播 MAC、历史唯一资产且本任务 MAC 不重复时关联。
   不凭 IP、名称、端口、VMware 上下文认定身份。
2. 未取得 MAC、无效 MAC、重复 MAC、历史多个资产时自动建立 needs_review 档案，
   不合并已有资产。可能产生重复待核验档案，不能宣称解决无凭据设备身份。
3. 自动登记是 discovered，不是 managed；不授予采集授权。旧手动档案保持 managed。
   所有关联注明 automatic_discovery；自动决策逐发现持久化，重跑不重复写入；
   人工撤回不能被自动补处理静默覆盖。
4. 默认北京时间09:00每天一次。Windows计划任务负责唤起项目 CLI，
   SQLite每日唯一执行记录与扫描锁负责去重、防重叠。手动扫描不消耗每日名额。
   关机不能扫描；登录补当天到点任务，不积压补扫过去每一天。
   失败/部分完成保留结果，不自动无穷重扫；可手动重新扫描。
5. 不开放未经认证的远程扫描写 API，不改前端，不改目标机器地址/防火墙。
   本地配置保存授权范围；算法不写死实验地址。升级前一致性备份。

## 文件职责

- `app/assets/automatic.py`：扫描后通用自动登记/关联，持久化判断条件。
- `app/assets/models.py`、`app/assets/service.py`：保留原人工登记，新增来源与身份状态。
- `app/scheduling/models.py`、`app/scheduling/service.py`：每日运行记录与到期判断。
- `app/scheduling/cli.py`：run-due/status，项目入口而非AI定时提醒。
- `app/discovery/execution.py`：手动/定时共享真实探测与报告逻辑。
- `migrations/versions/0003_automatic_discovery.py`：兼容旧库增量升级。
- `scripts/manage-daily-scan.ps1`：Windows任务安装、检查、禁用/移除。
- `tests/test_automatic_assets.py`、`tests/test_daily_scan.py`：独立库验证，不造真实结果。

## 已知身份限制

MAC可以改变、克隆；ARP可能命中缓存。上述是可解释的资产关联策略，不是设备认证。
物理多网卡默认可能分为不同资产。scope是人工命名逻辑网络，换物理网络须换scope名。
后续可信Agent注册/凭据认证才能增加更强的设备身份依据，本轮不假装已实现。
