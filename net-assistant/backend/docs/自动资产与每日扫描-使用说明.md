# 自动资产档案与每日扫描（后端0.4.0）

日期：2026-11-15，北京时间。当前是本机后端功能，不是说明网站、宝塔服务或Codex提醒。

**0.5.0 更新：自动资产策略继续有效；每日托管已迁移到不依赖个人登录的 Windows 服务。**
**本文第4节的 Interactive 任务为历史/回退说明，不再是当前默认，勿和新服务同时启用。**
当前操作、换机限制与状态接口见 `后台服务与调度状态-使用说明.md`。

## 1. 扫描结束后，程序自己做什么

手动与每日扫描调用同一执行器：

```text
读取授权范围和端口配置
→ 校验管理机源地址
→ ICMP / ARP / TCP发现
→ 配置端口检查、按条件取证
→ 保存发现和原始探测
→ 结束任务并自动创建/关联资产
→ 保存决策规则、关联与审计
→ 导出任务报告
```

没有一段“AI根据结果填资产”的必要步骤。自动记录 actor=automatic_discovery。
管理名称默认“发现设备 + 本次IP”，只作标签；UUID才是档案标识。
程序不根据Windows/Kali名称、VMware配置或135/445等端口判断设备身份。
旧版两台档案由AI调用人工CLI登记，仍如实保留manual来源，不追改成自动生成。

## 2. 判断是否为原资产：策略v1

| 情况 | 程序动作 | 持久化规则 |
|---|---|---|
| completed/partial且有直接响应；有效MAC无历史匹配 | 新建UUID并关联发现 | new_mac |
| 同scope；MAC规范化后历史只指向一个资产；本次未重复 | 沿用该UUID，追加本次发现和地址观测 | unique_mac_same_scope |
| 同IP但MAC不同 | 不凭IP合并；该MAC无历史则新建，否则关联其自身历史资产 | 取决于MAC历史，不以IP决定 |
| 无MAC、无效/全零/广播/组播MAC | 新建待核验档案，不凭IP/名称沿用身份 | missing_or_invalid_mac |
| 本次任务多个地址出现相同MAC（包括候选） | 为响应设备分别建待核验档案，不合并历史资产 | duplicate_mac_in_scan |
| 一个MAC历史已关联多个资产 | 新建待核验档案，不替管理员猜是哪台 | ambiguous_mac_history |
| 不同scope | 不跨scope匹配；分别建档 | 本scope内计算 |
| 只有ARP解析/拒绝等候选，无直接响应 | 只保留发现证据，不自动建档 | no_direct_response |
| 任务running/failed/interrupted | 不运行自动关联 | 必须先有可用的结束任务 |
| 发现已有人确认的关联 | 保留，不覆盖名字/分类/负责人 | preserve_explicit_link |
| 同一发现已自动处理 | 不重复建档、不追加重复审计 | durable decision |

MAC规范化处理大小写、冒号/连字符。策略不授予任何主机采集权限。
固定UUID只保证台账编号不随IP改变，不保证网络设备的身份经过认证。

### 必须了解的限制

- MAC可以克隆、更换，ARP可能命中缓存；当前是网络线索关联，不是可信设备认证。
- 即使历史唯一，也无法排除一台克隆设备先后替换原设备；API始终identityVerified=false。
- 无MAC/冲突时，重复扫描可能产生多个needs_review档案，这是保守取舍，
  不是“所有设备都能无误去重”。本轮不做自动物理多网卡合并。
- scope由配置name定位。同一网段在不同物理网络可能重复，换网络应换scope名。
- 自动档案managementStatus=discovered；registrationSource=automatic。
  旧人工登记档案managementStatus=managed，registrationSource=manual。
- identityStatus为observed_mac/mac_correlated/needs_review/manual_confirmed。
  manual_confirmed指管理动作，不是密码学身份认证。
- CPU/内存/进程仍未采集：collectionAccess=not_enrolled、hostMetrics=null。
- 人工unlink后重放同一任务不会自动把该发现绑回；后续新扫描仍按当前有效历史判断。
  这不是永久屏蔽某设备；当前未实现黑名单或人工身份拆分规则。

## 3. 手动扫描

PowerShell：

```powershell
Set-Location -LiteralPath "<checkout-or-user-tool-path>"
.\.venv\Scripts\python.exe -m app.discovery.cli scan --config configs/vmnet8.local.json
```

`scan`是真实发包。`validate`不发目标探测。`export`只导出已有任务。
当前实验配置是192.168.193.0/24，排除.1/.2/.254，115个常用TCP端口；
地址和端口都在JSON，不在算法写死。迁移到学校网络前重新确认授权并修改配置。
同时只能有一个扫描/台账写入者；已有任务时手动扫描返回scan_busy（退出码2），不启动第二次。
本轮没有网页扫描按钮或远程POST入口；不要把命令行功能描述为已交付操作页面。

## 4. 每天一次自动扫描

计划配置：

```text
<checkout-or-user-tool-path>
```

```json
{
  "name": "vmnet8-daily",
  "enabled": true,
  "at": "09:00",
  "utc_offset_minutes": 480,
  "scan_config": "vmnet8.local.json",
  "database": "../data/inspection.sqlite",
  "report_directory": "../reports"
}
```

- at为每天时间；480为固定UTC+08:00，即北京时间，不依赖UTC日志日期。
- 固定偏移不处理夏令时规则；当前中国实验环境适用。迁移到夏令时地区须重新设计/配置。
- 路径相对计划JSON文件，而不是当前命令行目录。
- name是每日去重键的一部分；不要为了改时间改name，否则可能新开当天执行名额。
- 范围/端口修改scan_config指向的配置；不要通过更换资产编号表达IP变化。

### 系统定时触发与项目去重各负责什么

Windows计划任务NetAssistant-DailyDiscovery在09:00唤起项目CLI，
另有当前用户登录触发和错过时间后运行设置。
项目CLI按北京时间检查到期及数据库每日唯一记录，尚未到点直接退出，不发包。

本机采用Interactive、Limited，不保存密码，不申请管理员权限：
**电脑需开机、当前用户已登录且实验网络可达。锁屏不是注销。**
关机、注销或虚拟机关闭时，不能承诺拿到设备数据；下次登录仅补当天已到点的一次，
不把停机过去每一天排队补扫。登录前未到09:00则等当天定时触发。

数据库以(schedule_name, local_date)唯一约束每日自动尝试，OS IgnoreNew加进程文件锁防重叠。
手动扫描不占每日名额。partial/failed/interrupted记为当天已尝试，不自动无限重扫，
需要时用手动扫描重新检查。撞上手动任务返回busy且不占名额；
当前计划任务最多间隔10分钟重试3次，超过后当天可能错过，需看日志/手动补扫。
程序崩溃留下的running在下一次获得锁并执行到期入口时标中断；
已完成扫描但最后调度回写中断的，按已结束扫描状态恢复，不重复发包。

### 安装、查看、暂停

```powershell
# 预览：校验配置，不注册、不扫描
.\scripts\manage-daily-scan.ps1 -Action Preview

# 安装或更新项目自己的任务（改at后重新执行）
.\scripts\manage-daily-scan.ps1 -Action Install

# 查看Windows是否安装、下次触发时间和上次退出码
.\scripts\manage-daily-scan.ps1 -Action Status

# 查看项目数据库中的每日实际执行历史；不会扫描
.\.venv\Scripts\python.exe -m app.scheduling.cli status --config configs/daily-scan.local.json

# 暂停自动扫描，不删除数据库
.\scripts\manage-daily-scan.ps1 -Action Disable

# 移除系统触发器，不删除数据库
.\scripts\manage-daily-scan.ps1 -Action Remove
```

若系统阻止本地脚本，单次使用powershell.exe -NoProfile -ExecutionPolicy Bypass -File
加脚本绝对路径与-Action；不需要修改整机执行策略。
本机安装脚本要求Windows当前UTC偏移与计划一致，避免悄悄装错触发时间。
转移工程目录、改Python环境、改计划文件路径后需要重新安装任务。

`run-due`为“检查到期并执行”而非无条件扫描：

```powershell
.\.venv\Scripts\python.exe -m app.scheduling.cli run-due --config configs/daily-scan.local.json
```

退出码：0=成功/未到点/禁用/已尝试；1=失败/部分完成/中断；2=已有写入者。
WindowsLastTaskResult=0只表示入口本次正常退出，**不能单独证明发生过扫描**；
必须结合项目status、任务job与原始证据。日志写入reports/schedule-logs/日期.jsonl。
HTTPAPI不开启调度，停止Uvicorn不等于停止已安装的Windows扫描任务。

## 5. 保存在哪里，前端如何读取

工作库仍为：

```text
<checkout-or-user-tool-path>
```

迁移0003_automatic_discovery新增：

- assets.registration_source、identity_status，旧人工档案默认manual/manual_confirmed。
- asset_identity_decisions：每条发现的自动决定、MAC/范围/候选证据和时间；防重复处理。
- scheduled_scan_runs：每日名额、状态、原因、计划快照。
- discovery_jobs.trigger（manual/scheduled）、schedule_run_id，串起调度与扫描任务。

旧有资产/关联/审计保留；原探测字段不被覆盖。升级前自动一致性备份。
迁移完成后再启动新版API，不在API中偷偷迁移。API仍只读。
旧GET接口和分页保留，前端增加读取以下字段即可：

- 资产：registrationSource、identityStatus、identityVerified。
- 发现关联：automaticDecision.rule/evidence，可解释这次为什么关联/未关联。
- 审计/观测：actor增加automatic_discovery，仍保留local_cli。
- 扫描：trigger、scheduleRunId、coverage.assetRegistration统计。

当前HTTP只读，无调度管理页面/调度设置写API；0.5.0增加只读调度状态与历史API。
最新版契约为docs/openapi-0.5.0.json，0.4.0及旧版文件保留作历史。
“每天自动扫描”不是每日数据库备份；自动备份轮换、Agent、CPU/内存/进程、
账号、故障防抖/恢复事件和业务页面仍不在本次完成范围内。
