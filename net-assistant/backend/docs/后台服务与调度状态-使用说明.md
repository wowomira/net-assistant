# Windows 后台服务与调度状态（后端 0.5.0）

日期：2026-11-15，北京时间。此文是当前操作入口；0.4.0 文档中的 Interactive 计划任务现为旧版回退方式。

## 一、实际工作链路

```text
Windows SCM（系统服务管理器）
  └─ 独立虚拟服务账户启动项目调度工作进程
       ├─ 每约 2 秒写一次原子心跳
       ├─ 每约 30 秒判断是否到期（不是每 30 秒重扫网络）
       └─ 到期 → 有界子进程调用原 run-due
                   → 共用扫描文件锁
                   → SQLite 每日唯一名额
                   → 真实探测、证据、自动资产关联、报告

手动 CLI → 同一个扫描执行器和扫描文件锁，不占每日名额
只读 FastAPI → 读心跳与 SQLite，不启动调度，不触发扫描
```

调度工作进程与 API 是两个运行职责；此次只给调度安装了系统服务。API 仍需按下文命令启动，没有顺手安装另一个 API 自启服务。关闭临时 API 不停止自动扫描。

### 当前本机配置

- 服务名称：`NetAssistant-Discovery`，启动类型 Automatic。
- 运行身份：`NT SERVICE\NetAssistant-Discovery`，不是管理员/LocalSystem，不保存个人密码。
- 正式计划：`configs/daily-scan.local.json`，北京时间每天 09:00。
- 授权范围仍由 `configs/vmnet8.local.json` 决定，未扩大范围或改变端口集。
- 原 `NetAssistant-DailyDiscovery` 任务已停用、保留；不要同时安装两种托管。
- 配置加载后固定为本次服务实例快照；修改时间、范围、端口或相关路径后，停止再启动服务才生效。接口会把旧实例标为 `configuration_changed`，不伪装已应用。
- 不热更新 IP、不自动获得新网络的扫描授权。

## 二、启动、停止和安装

PowerShell（CMD 不支持 PowerShell 的变量和 cmdlet）：

```powershell
Set-Location -LiteralPath "<checkout-or-user-tool-path>"

# 只读预览，不注册服务、不发包
.\scripts\manage-discovery-service.ps1 -Action Preview

# 只读系统托管状态
.\scripts\manage-discovery-service.ps1 -Action Status

# 下列管理操作需要管理员 PowerShell；本机已安装，不要重复 Install
.\scripts\manage-discovery-service.ps1 -Action Stop
.\scripts\manage-discovery-service.ps1 -Action Start
```

新机器准备好环境并核对配置后，才执行：

```powershell
.\scripts\manage-discovery-service.ps1 -Action Install
```

安装器会：

1. 解析并校验计划、范围、端口、基础 Python 位置。
2. 从当前工程生成带引号的启动命令，不写死本机工程路径。
3. 使用虚拟服务账户，授予本工程读取权限、数据库父目录与报告目录修改权限；仅对配置中存在的 VMX 文件授予读取权限，不批量授予虚拟机目录写权限。
4. 配置开机自动启动及异常退出后 10 / 30 / 60 秒的三次恢复，之后不无限重启；故障计数复位周期一天。
5. 真正启动并确认该配置的新实例心跳后，才停用本项目旧计划任务。启动失败则移除刚建服务、保留/恢复原任务的启用状态。

**注意：Install 会启动服务；如果计划已到期，可能立即执行当天扫描。Preview 不会。** 安装失败可能保留新增的目录/该虚拟账户 ACL，Remove 也保留数据和 ACL，不冒充“完整还原系统权限”；文件权限的独立清理尚未制作。

原生服务桥接使用 Windows 系统 API 和 Python 标准库，无新的第三方安装依赖。为避免虚拟环境启动器的进程重定向影响 SCM，SCM 直接启动基础 Python，再由项目 bootstrap 加载相邻 `.venv` 的依赖。

### 暂停、移除与回退

- 暂停：Stop；因为启动类型仍是 Automatic，下次开机可能再次运行。长期停用可以把计划 `enabled` 改为 false 后重启服务；工作进程还写心跳，但不扫描。
- 移除：先 Stop，再 `-Action Remove`。不删除库和报告，不自动启用旧任务。
- 有意回退旧方式：先 Stop、Remove 新服务，再执行 `manage-daily-scan.ps1 -Action Install`。旧方式需要个人用户登录，其局限仍存在。
- 不要为了重新安装直接删 `.venv`、数据库或扫描记录。服务存在时 Install 会拒绝覆盖；错误路径或解释器变化先停服务、移除注册、修正环境，再安装。

## 三、每日规则与失败处理

- 每个计划名称、每个本地日期最多一次正式自动尝试。手动扫描独立，不占该名额。
- 未到点、禁用不扫描，也不创建空数据库；工作进程的心跳文件可以先存在。
- 自动扫描与手动扫描共用扫描写锁；遇忙不占自动名额，工作进程后续再次检查。
- `completed / partial / failed / interrupted` 都计入当天已尝试；**不是保证每天成功一次**。失败可通过手动入口补查，不自动无限重扫。
- 错过时间只补当天，不补停机过去每天的积压。
- 正常停止会结束当前扫描子进程；Windows Job Object 约束已接管的扫描进程树，工作进程异常退出时一并清理。下次到期入口取得锁后恢复遗留 running 记录；状态 GET 不修复、不写库。
- 单次子进程上限为配置扫描预算加 120 秒。原有探测本身也保留超时/预算。
- 工作进程每次实际调用的日志仍在 `reports/schedule-logs/`。每 30 秒的到期判断不是目标连通性探测，更不是设备 10 秒级高频巡检。
- 操作系统关机、网络不可达、目标关闭、存储故障时不能承诺获得数据。服务恢复也不意味着网络扫描失败会自动再执行。

## 四、状态接口（只读）

启动 API：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-proxy-headers
```

默认工作库自动配本工程计划。独立库显式设置两项绝对路径，防止读 A 库却显示 B 计划：

```powershell
$env:INSPECT_DB = "D:\某工程\data\inspection.sqlite"
$env:INSPECT_SCHEDULE_CONFIG = "D:\某工程\configs\daily-scan.local.json"
```

`GET /api/v1/scheduler`：

| 字段 | 含义 |
|---|---|
| configured | 该 API 是否配置了每日计划；不表示 Windows 服务已经安装 |
| schedule | 名称、启用、每天时间、固定 UTC 偏移、本地日期、下一未消费名额的计划时刻 |
| worker.state | running / checking / stopped / error / stale / unknown |
| worker.lastInvocation | 最近一次到期检查的返回，不是最近一次扫描的成功证明 |
| database.state | available 表示支持的 schema 且本次读成功；不是磁盘可写/完整系统就绪证明 |
| todayStatus | 当天自动名额的执行状态；pending 表示到期未尝试，not_due 表示未到时间 |
| todayRun / latestRun | 本计划当天/最近一次自动尝试，含 jobId 与 errorCode；不包括手动扫描 |
| capabilities | 代码已具备/尚未实现的能力，不是用户权限或运行健康结论 |

`checking` 仅表示到期入口子进程在运行，可能只读取每日名额而不发包。`already_attempted` 只是当天已尝试，之前那次可能失败；必须同时看 `todayRun.state`。

心跳超过 90 秒为 stale；丢失、损坏、配置指纹不符或时钟明显倒退为 unknown。采用文件写入证据，不查询实时 SCM 进程，因此故障发现有心跳过期窗口；不把“新鲜”说成永不故障。`stopped` 保留明确的最后停止记录和时间。

原始数据库记录为 running 但没有正在执行到期入口的可信 checking 心跳时，
顶层 todayStatus 返回 unknown；只有空闲 worker 活着也不证明扫描还在跑。
保留 todayRun 原始证据，不由 GET 擅自改成 interrupted。

`GET /api/v1/scheduler/runs?limit=50&cursor=...`：

- 只查询本计划的自动执行历史；分页默认 50、最大 200。
- 不返回计划文件绝对路径或原始配置快照。
- 缺库返回空列表、不建库；有库但不兼容/不可读则 503。
- 读取状态/列表都不发包；POST 返回 405。状态接口不等于远程管理接口。

既有发现/资产只读 API 不变；`/health/live` 仍只表示 API 存活，`/health/ready` 仍未实现。新接口不是完整就绪检查。

## 五、文件与迁移

- 工作库：`data/inspection.sqlite`，继续 schema `0003_automatic_discovery`，本轮没有迁移或人工填业务记录。
- 心跳：数据库父目录的 `runtime/<plan-name>.json`，临时文件原子替换。
- 工作进程锁与启动快照：同一 runtime 目录；崩溃可能残留临时快照，不作为业务事实。
- 正式范围、计划保持 configs 文件；每次执行保存扫描配置快照，实际服务实例使用的冻结文件路径可能在 runtime 中。
- 验收证据在 `reports/task05-service/`，不向工作库导入独立验证资产。
- 共享进度数据库与 `/api/progress` 完全独立，本轮未修改。

## 六、换机和跨平台边界

新 Windows 电脑需要：安装受支持 Python、重建 `.venv` 并安装依赖、修改源网卡/授权范围/可选 VMX 路径、按需迁移 SQLite 数据、重新安装服务。**不是复制旧 `.venv` 或系统服务即可运行。** 配置名称是逻辑 scope，不是物理网络自动识别；换实验网络应重新明确 scope 和授权。

服务安装器只允许项目内的计划、扫描配置、数据库及报告目录，避免错误授权任意系统目录。安装器从当前目录生成绝对路径；工程或基础解释器移动后必须重新安装。

Linux、飞牛、宝塔没有本轮验证的服务适配，源网卡验证和部分原生探测也未实现平台对等能力。将说明网站部署到宝塔，不等于宝塔能扫描 VMware NAT；必须有真实网络路由和授权，不能只改部署位置。
