# 任务 02：可配置资产发现、服务证据与数据库

依据：用户批准按范围发现，先检查较完整的常用 TCP 端口，要求不写死网段，
并保存、解释真实采集结果。本任务不等于后续全部持续巡检功能。

## 决策与边界

- 扫描范围接受 IPv4 单地址、CIDR、起止范围，支持排除地址。
  本次授权网段只写入本机实验配置，不写入算法和迁移。
- 常用 TCP 端口使用可编辑 JSON 配置；报告列出完整清单与覆盖量。
  不声称有限清单包含所有服务，不做 UDP、漏洞或口令测试。
- 发现综合 ICMP、同链路 ARP、可配置 TCP 补充探测；不能仅以禁 ping 排除设备。
- 对本次直接响应/ARP 解析候选做完整配置端口检查；ARP 候选不等于当前在线，未发现不等于不存在。
- 信息增强仅做 HEAD、保持校验的 TLS、有限被动横幅读取；不自动跟随重定向，
  不传系统代理，不下载完整网页，不发数据库/登录协议探测。
- VMware 配置作为可选本机上下文，只在实时 MAC 对应时关联。
  配置名称、guestOS 与网络实际识别严格分开，不把过期租约算在线。
- 增加独立 SQLite、SQLAlchemy 2.0、Alembic；不接触 Node 进度库。
  保存范围配置版本、任务快照、发现快照、每次探测、覆盖和错误。
- 先用本机 CLI 发起扫描，API 只读。权限系统尚未实现，不新增无鉴权扫描 POST。
  原存活接口不改变，不伪造就绪。
- 默认受控并发 6；超时、预算、地址数量上限可配置。
  未完成、失败、重启中断与“目标没有响应”分别表达。

## 用户追加分类要求

发现快照已增加纳管状态、主机采集状态与业务类型，默认发现待确认/未接入/未知。
不因扫描范围或 VMware 名称授予主机采集权限。完整资产台账、分能力授权和 Agent 后续独立实施，
见《资产分类与授权边界》。本轮 HTTP/TLS/banner 适配器有测试，但真实扫描没有命中取证端口，
不能把它们写成本次虚拟机已取得的证据。

## 本轮不做

业务大屏、周期调度、防抖事件、账号系统、CPU/内存代理、
设备自动纳管、真实系统修复、全端口默认扫描和公网部署。
