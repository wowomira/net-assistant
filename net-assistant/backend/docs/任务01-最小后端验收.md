让独立的 Python 后端能响应存活请求，并具备可重复执行的测试、启动说明和精确依赖锁。

- Python 3.13.7，64 位；项目使用自己的 `.venv`。

- 实测版本以 `requirements.txt`、`requirements-dev.txt` 为准，包含传递依赖。

  诊断后仅在安装子进程环境中为 PyPI 添加 `NO_PROXY`，未更改系统代理或用户 pip 配置。
- 本轮未升级全局 Python、pip，也未进行完整依赖漏洞或许可证审计。

## 接口和实现

- `GET /health/live`：200，`{"status":"alive"}`，`Cache-Control: no-store`。
- 响应使用 Pydantic 模型声明，OpenAPI 中操作 ID 为 `getLiveness`。
- 存活仅说明应用能响应，不能说明数据库、调度或被测目标正常。
- `/health/ready` 尚未实现，保持 404。
- 说明网站的 `/api/progress` 不注册在这个应用中，保持独立。
- 默认启动说明只允许回环访问、单 worker、不信任代理转发头。
- 不把返回 alive 的对象计为“健康设备”，不伪造巡检数据。
