# 前端对接说明

适用源码版本：**0.10.0**。核对日期：**2026-11-16**。本文以当前协作仓库源码为基线，不代表任何旧后台进程已自动升级。

本文给前端开发者说明：怎样启动、怎样登录、每个页面从哪里取数据、如何解释失败及缺失状态。
不规定页面布局，也不要求使用现有 React 页面。**项目是前后端分离的源码与 HTTP 接口契约；同源托管只是推荐部署方式，不是把前端业务写进后端。**

- 机器可读契约：[openapi-0.10.0.json](openapi-0.10.0.json)；本版共 **48 个路径／48 个操作**，完整方法与路径见第10节。
- 运行中契约：自己启动的后端 `/openapi.json`，先检查 `info.version === "0.10.0"`。旧 `openapi-0.9.0.json` 仅作历史。
- 环境准备：[仓库 README](../../../README.md)和[Windows协作与离线运行](../../../docs/Windows协作与离线运行.md)。
- 既有客户端：[src/api.ts](../../frontend/src/api.ts)；生成类型：[src/api-schema.d.ts](../../frontend/src/api-schema.d.ts)。
  目前客户端主要是只读查询封装，**没有现成的完整登录页、改密页、会话恢复或网页SSH终端**；下文示例需由前端集成，不是已经自动装好的页面。

**先看能力边界：**扫描、资产、采集与监控有查询接口；登录及受控SSH有后端接口；
没有面向浏览器的扫描触发、任意资产编辑、原始按键终端或自动保存／回滚接口。
一键配置仅预留契约，无可执行模板和执行器。多厂商目录不是实机兼容承诺；没有目标或凭据时返回真实空状态，不补假数据。

## 0. 前端先读：最短联调路径

### 0.1 取得环境，先让后端独立跑起来

1. 克隆 `wowomira/net-assistant`，按 README 下载与 `runtime.lock.json` 匹配的 Release 资源，校验后解压到仓库根。
2. 以下 PowerShell 命令均在**仓库根目录**执行，不依赖作者的盘符、用户名、全局Python或Node目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 setup
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 init
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 create-user yourname --role admin
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 doctor
.\start.cmd
```

将 `yourname` 换为自己的用户名；建号用户名3～64个ASCII字母、数字或 `_.-`，密码12～128字符，
在本机隐藏提示中输入。没有默认账户、自助注册或共享密码。`ExecutionPolicy Bypass` 仅作用于该次进程，不是管理员／驱动授权。

3. 保持启动窗口运行，打开 `http://127.0.0.1:8001/docs`；检查 `/openapi.json` 的版本以及 `/health/live`。
4. 先在同一浏览器的 Swagger 执行 `POST /api/v1/auth/login`，再打开 `http://127.0.0.1:8001/console/` 看现有只读工作台。
   前端实现自己的登录页后，用相对地址 `/api/v1/auth/login` 替代这一步。不要换成另一个主机名后假定Cookie仍可用。

**纯源码克隆 + 公开资源首次运行是空库，无作者的真实历史、账号或设备凭据。**
可选私人历史种子须另外获准交付，不在GitHub或公开Release中；历史仍走相同查询接口，不新增“演示接口”。
历史时间不因换电脑而刷新，也不自动变成当前在线。空库不妨碍完成登录、空状态和错误状态开发；
需要有数据联调时，由后端在授权环境真实采集或另行提供获准的私人种子，不能把fixture冒充真实业务。
扫描所需Nmap/Npcap等前提见README；单纯制作前端不需要先连接真实设备或执行扫描。

### 0.2 两种前端运行方式：推荐同源，也可独立热更新

**方式A：后端同源托管构建结果。** 编辑 `net-assistant/frontend/src/`，而不是 `.runtime/frontend/src/`。
重新运行 `bootstrap.ps1 setup` 会同步源码并构建项目内前端；随后通过 `8001/console/` 联调。
这是最少Cookie、Origin及代理问题的起点，不代表源码不分离。

**方式B：前端Vite开发服务器。** [vite.config.ts](../../frontend/vite.config.ts) 默认把
`/api`、`/health` 和 `/openapi.json` 转发到 `http://127.0.0.1:8001`。
若显式选择了其他后端端口，请相应修改配置中的 `backend.target`。
`changeOrigin: false` 保留浏览器入口的Host，后端会用它校验原始Origin。
不要擅自改成 `true`、改写Origin或关闭同源检查。Vite是开发工具，不作为对公网的生产代理。
在新的PowerShell窗口、仓库根目录执行：

```powershell
$env:Path = "$PWD\.runtime\tools\node;$env:Path"
Push-Location .\net-assistant\frontend
npm ci --cache ..\..\.runtime\npm-dev-cache
npm run generate:api
npm run dev
# 停止开发服务器后执行 Pop-Location 返回仓库根目录。
```

开发入口为 `http://127.0.0.1:5182/console/`。源码目录的 `npm ci` 与 `.runtime/frontend/` 的准备是两件事；
首次安装开发依赖可能需要联网，不能因为配套资源支持离线构建就认定上述独立开发安装也必然离线成功。
浏览器请求统一使用相对路径 `/api/v1/...`，从5182入口完成登录／me恢复；
不要在前端直接fetch8001，再用CORS错误或关闭认证掩盖入口不一致。

### 0.3 页面／模块与接口对应表

以下是接入分工，不是强制页面布局。路径均为完整路径；ID来自真实返回值并经 `encodeURIComponent` 编码。

| 前端模块 | 首批接口 | 关键接收规则 |
|---|---|---|
| 登录、顶部用户区、改密 | `POST /api/v1/auth/login`、`GET /api/v1/auth/me`、`POST /api/v1/auth/password`、`POST /api/v1/auth/logout` | 先恢复会话；Cookie由浏览器管理；写请求带CSRF，见8.1、8.7 |
| 首页／总览 | `/api/v1/scheduler`、`/api/v1/switches/status`、`/api/v1/monitoring`，按需读任务／资产列表 | **没有一个已实现的通用dashboard聚合接口**；分页第一页不能当全库总数或最新记录 |
| 扫描任务列表／详情 | `/api/v1/discovery-jobs`、`/api/v1/discovery-jobs/{job_id}` | 只读历史；不因点刷新触发扫描 |
| 主机／证据／比较 | `/api/v1/discovery-jobs/{job_id}/hosts`、`.../probes`、`.../comparison` | 区分扫描任务与设备；探测可按address/method/status筛选；比较unavailable显示原因 |
| 网站截图 | `/api/v1/discovery-jobs/{job_id}/screenshots/{probe_id}` | 仅引用真实成功证据；返回PNG，不走JSON解析器；缺图显示缺失，不造占位证据 |
| 资产台账／关联／审计 | `/api/v1/assets`、`/api/v1/assets/{asset_id}`、`.../observations`、`.../audit`、`/api/v1/discovery-hosts/{host_id}/asset-association` | 稳定资产与单次发现是不同对象；本版未提供通用台账写接口 |
| Windows本机网络 | `/api/v1/network-devices`、`/api/v1/network-devices/{device_id}/snapshots/latest`、`.../snapshots`、`/api/v1/network-snapshots/{run_id}` | 是采集机，不是全网电脑清单；内层snake_case保留，见第6节 |
| 交换机／端口／转发表／LLDP | `/api/v1/switches/status`、`/api/v1/switches`、详情、快照与 `/api/v1/switch-collection-runs` | 先看本次状态，再消费snapshot；失败不回填旧成功为本次，详见4、5节 |
| 监控／调度历史 | `/api/v1/monitoring`、`/api/v1/monitoring/{endpoint_id}`、`/api/v1/scheduler`、`/api/v1/scheduler/runs` | 监控不是Page分页；定时历史不含手动扫描；Gatus不可用不等于全部设备离线 |
| 受控SSH操作台 | `/api/v1/terminal/targets`、`.../commands`、会话、预览、确认、执行、事件 | 按第8节分阶段接入，不是xterm原始按键透传；绝不选择命令就自动执行 |
| 一键配置 | `/api/v1/terminal/configuration-templates` 等预留接口 | 当前禁用并说明“未实现”；不能显示可执行模板或成功历史 |

### 0.4 前端必须分别呈现的状态

- 首次加载、成功有数据、成功为空、读取失败、会话失效、权限不足、未配置、旧结果／过期状态分别处理。
- `HTTP 200` 不等于采集成功或SSH已就绪；继续检查响应的 `state`、`status`、`errorCode`、观测时间。
- 网络错误或 503 时可保留已读取的数据并显示错误。401 会清除工作台数据并提示重新登录；403 会清除被拒绝资源的数据，并显示服务端原因。
- 历史任务数量不是设备数量；资产、发现、SNMP设备、终端目标ID不可互换。
- 没有历史、截图、终端目标或监控目标时显示真实空状态；测试fixture必须明确隔离且标注，不作为生产兜底。
- 建议先完成“会话恢复 → 登录 → 只读列表／详情 → 失败与空状态”，再做受控终端；不要把尚未实现的一键配置列为本轮验收成功。

### 0.5 类型生成与代码使用约定

- 前端源码目录执行 `npm run generate:api`，从仓库中的 `openapi-0.10.0.json` 生成 `src/api-schema.d.ts`；
  再执行 `npm run typecheck`。这是类型生成，不会生成登录页面、业务状态处理或已配置的请求客户端。
- 可从 `components["schemas"]["JobView"]`、`AssetView`、`HostView`、`ProbeView` 等组件取类型。
  协作者使用其他框架／目录时，也可直接从同一JSON生成对应类型，不强制复用React。
- 下文 `readJson`／`postJson` 的 `path` **不含** `/api/v1` 前缀，例如传 `/assets`；
  第10节完整URL目录则包含该前缀。不要拼成 `/api/v1/api/v1/...`。
- 示例以浏览器Fetch为基础；TypeScript泛型不会自动验证运行时响应。动态监控、交换机快照和目录字段按本文补充模型处理。
- 现有客户端的 `ApiError` 与本文示例的 `ApiFailure` 是不同封装，不要把两套名字混着复制。
  全部 `ts` 代码块可以合为接入示例模块；接入实际工程时统一为一个请求层，再给页面提供函数。
- 本文示例接收代码不自动加入超时；可用 `AbortController` 取消GET或限制等待。
  现有只读客户端已有15秒读取超时；写请求超时／取消不等于后端撤销，尤其执行操作要先查询原operation。

**后续查阅：**第1～3节是入口、公共规则与错误；第4～7节是业务结构；
第8节是认证与受控SSH；第9节是联调验收；第10节是完整接口索引。接口之外的新交互需求先确认后端契约，不能只画按钮就默认已有能力。

|---|---|
| 项目内默认地址 | `http://127.0.0.1:8001`；启动后才可用，以实际进程和配置为准，不接管其他旧端口服务 |
| 业务前缀 | `/api/v1` |

| 后端负责 | 授权范围、真实采集、归一化、持久化、分页、状态、错误、时间及来源 |

| 网络访问边界 | 推荐启动只监听本机；跨机部署需另行配置HTTPS、可信入口及安全策略，不等于公开GitHub后本地API也公开 |

不要通过 `mode:"no-cors"` 绕过跨域，所得不透明响应不能作为可读取的JSON。

遇到 `origin_rejected` 时由前后端核对入口、Host及代理规则，不移除Origin检查、不伪造请求头规避。
第0.2节只说明可选开发代理；不要求开放防火墙、改变监听到所有网卡、接管旧服务或关闭安全校验。

### OpenAPI当前覆盖的限制

- 0.10.0共48路径／48操作：原27个GET、4个认证操作、17个终端操作（包含一键配置预留）。方法与完整路径见第10节。
- 设备、运行记录、资产、扫描、本机网络快照及调度有响应模型，可以据此生成类型。
- `/monitoring`、`/monitoring/{endpoint_id}`、`/switches/status` 的自动响应schema当前为空；其实际结构见本文第5、7节。
- `SwitchRunView.snapshot` 在自动schema中只是自由对象，交换机快照的细节见第4节。
- 新版OpenAPI补齐Cookie、CSRF安全要求及真实错误信封；422使用 `ApiErrorEnvelope`，不是 `{detail:[...]}`。
- 认证会话、终端会话和命令操作有响应模型；目录、事件等动态对象详见第8节，不捏造完整自动类型。

## 2. 通用数据规则

| 规则 | 前端处理要求 |
|---|---|
| 字段命名 | API外层通常camelCase；Windows本机快照内层保留snake_case。**不要对所有对象统一改名** |
| 标识符 | `id`、游标都是不透明字符串，不从中解析设备身份，也不要转为数字 |
| 时间 | 时间戳带 `Z` 或明确时区偏移；用日期库或Date解析，不自行补8小时。`localDate`是调度的本地日期，不是时间戳 |
| 空值 | `null`表示未读取／不存在／不适用，结合状态解释；不能转为0、离线或不支持 |
| 缺省字段 | 动态状态及历史数据可能没有某些字段，按本文可选项处理 |
| 空数组 | `items:[]`、`interfaces:[]`等表示没有返回记录，不等于请求失败，也不自动证明设备不支持 |
| 计数 | 交换机Counter64以十进制字符串返回；精确运算使用BigInt，显示时保留字符串；JSON输出不能直接序列化BigInt |
| 来源 | 管理标签、网络观测、程序判断分别处理；`identityVerified:false`不能当成已认证身份 |
| 不可信文本 | 设备名、描述、网页标题、远端端口标识等只作文本处理，不作为HTML执行 |
| 缓存与追踪 | `/api/v1/`响应有 `Cache-Control:no-store`，返回 `X-Request-ID`；请求失败保留编号便于后端定位 |

### 分页：从旧到新，不是最新优先

所有 `Page<T>`：

```ts
export interface Page<T> {
  items: T[];
  nextCursor: string | null;
}
```

- 参数 `limit` 默认50，范围1～200；`cursor`由上一页的 `nextCursor` 原样传回。当前契约限制为1～18位十进制数字字符串，仍视为不透明字符串，不转换成JavaScript Number。
- 当前实现按插入序号**升序**。下一页取序号更大的记录，游标不是页码。
- `nextCursor:null`表示本次读取没有下一页；不代表之后不会产生新数据。
- 不能凭第一页判断全库最新任务／最新尝试；需要专门的 `latest` 接口，或读完相关分页。
- 读取中数据可能增长，分页不是事务级静态快照。若要求某时刻一致的导出，需要另行约定。
- 监控的 `items/history`不是该分页结构，见第7节。

## 3. HTTP错误与请求示例

已注册业务路由的领域错误及参数校验错误：

```ts
export interface ErrorEnvelope {
  code: string;
  message: string;
  requestId: string;
  fieldErrors: { field: string; message: string; type: string }[];
}
```

| HTTP | 常见含义 |
|---|---|
| 200 | 请求成功；仍须检查数据内部的采集／运行状态 |
| 400 | 登录传输条件不满足，例如 `https_required` |
| 401 | `authentication_required`时清理本地认证；`invalid_credentials`按登录／改密场景处理，见8.9，不无限重试 |
| 403 | `csrf_rejected`／`origin_rejected`／`terminal_permission_denied` |
| 404 | 业务记录不存在，例如 `switch_not_found`、`switch_snapshot_not_found` |
| 409 | 会话不可用、预览过期、确认缺失、命令未获启用或终端繁忙 |
| 413 | 管理请求超过32KiB，包括分块传输；不要重试原大请求 |
| 422 | 模型校验为 `validation_error`，可读 `fieldErrors`；领域校验也可能是 `command_parameters_invalid`、`confirmation_phrase_invalid` 等，不保证总有字段级明细 |
| 429 | 登录限流，等待后再试；不靠自动连续重试绕过 |
| 501 | 一键配置尚不可执行，不是执行成功 |
| 503 | 数据库、配置或上游暂不可用，例如 `database_unavailable`、`switch_configuration_invalid`、`gatus_unavailable` |
| 网络失败／其他HTTP错误 | 单独处理，不转成空数据；未匹配路由的404、405及非预期500不保证是上述信封 |

以下接收函数只依赖浏览器Fetch。泛型是编译期约束，不代替运行时schema校验：

```ts
export class ApiFailure extends Error {
  constructor(
    public status: number,
    public code: string,
    public requestId: string | null,
    message: string,
    public fieldErrors: ErrorEnvelope["fieldErrors"] = [],
  ) { super(message); }
}

export async function readJson<T>(path: string, signal?: AbortSignal): Promise<T> {
  // 同源或开发服务器代理；path使用下文已约定的业务路径。
  const response = await fetch(`/api/v1${path}`, {
    method: "GET", credentials: "same-origin", headers: { Accept: "application/json" },
    cache: "no-store", signal,
  });
  const payload: unknown = await response.json().catch(() => null);
  if (!response.ok) {
    const error = payload && typeof payload === "object"
      ? payload as Partial<ErrorEnvelope> : {};
    throw new ApiFailure(
      response.status,
      typeof error.code === "string" ? error.code : "http_error",
      typeof error.requestId === "string" ? error.requestId
        : response.headers.get("X-Request-ID"),
      typeof error.message === "string" ? error.message : `HTTP ${response.status}`,
      Array.isArray(error.fieldErrors) ? error.fieldErrors : [],
    );
  }
  if (payload === null) {
    throw new ApiFailure(response.status, "invalid_json",
      response.headers.get("X-Request-ID"), "响应不是有效的非空JSON");
  }
  return payload as T;
}

export async function readAll<T>(
  path: string, signal?: AbortSignal, maxPages = 100,
): Promise<T[]> {
  if (!Number.isInteger(maxPages) || maxPages < 1) throw new Error("分页上限必须为正整数");
  const separator = path.indexOf("?");
  const pathname = separator < 0 ? path : path.slice(0, separator);
  const query = new URLSearchParams(separator < 0 ? "" : path.slice(separator + 1));
  query.set("limit", "200");
  const items: T[] = [];
  const visited = new Set<string>();
  const initial = query.get("cursor");
  if (initial !== null) visited.add(initial);
  for (let pageNumber = 0; pageNumber < maxPages; pageNumber += 1) {
    const page = await readJson<Page<T>>(`${pathname}?${query}`, signal);
    items.push(...page.items);
    if (page.nextCursor === null) return items;
    if (visited.has(page.nextCursor)) throw new Error("重复分页游标");
    visited.add(page.nextCursor);
    query.set("cursor", page.nextCursor);
  }
  throw new Error("达到分页上限，请按页加载或缩小查询范围");
}
```

`readAll`接受业务相对路径并保留已有查询条件，例如
`/discovery-jobs/{job_id}/probes?address=192.0.2.10&method=tcp`；自行构造筛选串时使用 `URLSearchParams`。
默认最多100页，到上限仍有数据时显式报错，不把截断结果当完整数据。终端事件增量读取另见8.8，不要套用全历史重读。
记录多时按页消费，不必每15秒重读全部历史。
请求可以取消；上一次未完成时不要不断叠加请求。业务需要自动刷新时，可在一轮请求结束后等待约15秒再发下一轮。
后台采集独立运行，GET、刷新页面或关闭页面都不应触发／停止采集。
临时网络或服务错误时可以保留旧结果并标明读取时间；收到 401 或 403 时应清除相应的旧数据。

### 面板数据的正确解释

| 数据 | 解释与边界 |
|---|---|
| `deviceKind` | `switch_product`表示设备报告了已识别的交换机产品族OID；另一种只确认锐捷企业信息，设备类别待核验 |
| `id/address/assetId` | 稳定标识的是配置范围内的管理端点，不是经认证的物理资产；不按IP自动合并到资产台账 |
| `interfaces` | 网络接口不一定都是机箱物理端口。不能凭数组下标、接口数量推断面板孔位或机箱型号 |
| `ifIndex` | 协议接口编号，不是物理端口顺序；名称可为空，`Gi0/7`等也是设备报告的文本 |
| `adminStatus/operStatus` | 管理状态与运行状态不同；协议中的 `up` 不统一翻译成“已启用且链路在线” |
| `speedMbps` | 设备报告的接口速率，不是应用层吞吐；不能代替实时流量曲线 |
| `inOctets/outOctets` | 累计字节字符串，不是每秒值。跨快照差分需先处理重启、计数回退及时间差；目前后端未提供可靠的实时速率字段 |
| `bridgePort/ifIndex` | 只有读取到桥端口映射才填ifIndex，未映射为null；不能认为两者相等 |
| `fdbId/vlanIds` | FDB编号不等于VLAN；映射可能多个、为空。基础转发表不自动补VLAN1 |
| `localPortNumber` | LLDP本地端口号，当前不等于 `ifIndex` |
| `capabilities` | 表／列分别记录读取状态；空表可能没有记录或未开放，不武断认定“不支持” |
| 未提供字段 | 私有CPU、内存、温度、PoE功率、机箱正面孔位、完整VLAN配置、终端连接状态，均不可由前端自行补成已采集 |

### 采集记录与能力状态

| 状态 | 语义 |
|---|---|
| `running` | 尝试未结束，快照为空 |
| `completed` | 本次采集完成；仍可能有合法空表，不等于每个指标都有值 |
| `partial` | 保留本次实际取得的部分数据，查看分项／分列状态 |
| `failed` | 本次失败，快照为空；不得自动把历史成功结果当本次数据 |
| `ignored` | 非锐捷设备，本次跳过，快照为空 |
| `interrupted` | 停止或前一进程中断，快照为空 |
| 能力 `available` | 该表／列有返回记录 |
| 能力 `no_data` | 无记录或未暴露 |
| 能力 `limited` | 列读取达到上限，不是全量；表汇总通常为partial |
| 能力 `not_collected` | 本次尚未读取，例如预算耗尽 |
| 能力 `failed/partial` | 列失败／表中存在未完成分项，查看列状态与原因 |

常见 `errorCode/reasonCode`：`snmp_timeout`、`snmp_authentication_failed`、
`snmp_access_denied`、`snmp_agent_error`、`snmp_protocol_error`、
`snmp_collection_failed`、`not_ruijie_device`、`collection_budget_exceeded`、
`row_limit`、`empty_or_not_exposed`、`switch_worker_stopped`。
其他码保留原始字符串，不把未认识的错误码当成功。

### 6.1 列表、详情与证据的关键字段

完整类型、必填／可空及枚举仍以OpenAPI为准，下表用于前端快速找到数据，不取代schema：

| 返回类型 | 首先关注的字段 | 不要误读 |
|---|---|---|
| `JobView` | `id,scopeId,scopeRevision,state,startedAt,finishedAt,coverage,errorCode,trigger,scheduleRunId` | 一个扫描任务不是一台主机；`configSnapshot`是历史参数，不是新电脑活动配置 |
| `HostView` | `id,jobId,address,mac,observedAt,confidence,openPorts,services,websites,assetId,associationStatus` | 同一地址跨任务可有多条发现；hostname／厂商／OS候选不等于已确认身份 |
| `ProbeView` | `phase,method,port,status,durationMs,reasonCode,evidence,observedAt` | 失败原因和证据要保留；请求成功不表示每一条探测成功 |
| `AssetView` | `id,name,assetKind,owner,revision,identityStatus,identityVerified,linkedObservationCount,lastObservedAt` | 人工管理资料与网络观测分开；身份未认证不包装成已核实 |
| `AssociationView` | `assetId,associationStatus,requiresConfirmation,candidates,ambiguous,addressConflict,confirmable,automaticDecision` | 返回候选／可确认状态，不代表前端已有可提交确认的HTTP接口 |
| `LinkedObservationView`／`AssetAuditView` | `discoveryHostId,jobId,observedAt`／`action,reason,actor,assetRevision,occurredAt,details` | 前者是关联观测，后者是变更审计；不要混为实时扫描输出 |
| `DeviceView`／`SnapshotView` | `assetId,associationSource,source`／`deviceId,state,observedAt,errorCode,snapshot` | 本机采集与资产编号不同；最新快照也可能失败，不能拿旧成功冒充本次 |
| `ComparisonView` | `status,reasonCode,baselineJobId,addedAddresses,notObservedAddresses,macChanges,probeChanges` | `notObservedAddresses`是未再次观察到，不是断言设备离线；无基线时不造变化 |
| `SchedulerView`／`ScheduledRunView` | `configured,schedule,worker,database,todayStatus,latestRun`／`localDate,state,errorCode,jobId` | 配置启用、工作进程存活、数据库可用、扫描完成是不同条件 |

探测列表除 `limit,cursor` 外支持 `address,method,status`，同一页翻页保留相同筛选值。
字段值来自真实记录，示例IP `192.0.2.10` 仅用于协议演示，不是默认扫描目标。
截图请求返回 `image/png`；可用同源图片URL，或先检查HTTP状态再 `response.blob()` 创建Object URL。
切换图片／卸载组件时释放Object URL；登录过期的JSON错误或404不能作为PNG读取，缺失截图不得自动替换成“已成功采集”的示意图。

### 6.2 三个易混点

1. `HostView`的 `confidence:"candidate_only"`不是确认在线；开放端口观测不等于所有业务健康。
2. `hostMetrics:null`、`hostMetricsStatus:"not_collected"`不是CPU或内存占用为0。OS候选、厂商线索也不是认证结论。
3. 本机快照外层 `observedAt`，内层 `snapshot.observed_at`、`interfaces[].interface_index`、
   `addresses[].prefix_length`等保留原名；邻居的 `online_verified:false`说明缓存不等于在线证明。

## 7. Gatus监控动态结构

```ts
export interface MonitorResult {
  success: boolean;
  statusCode: number | null;
  durationMs: number;
  observedAt: string;
  errors: string[];

export interface MonitorItem {
  id: string;
  key: string;
  url: string;
  assetId: string | null;

```

- 列表返回已配置监控目标；`available`表示上游接口可用，不表示每项目标都up。

## 8. 平台登录、受控SSH与一键配置预留（0.10.0）

### 8.1 平台登录：先接这一层

所有路径仍加 `/api/v1` 前缀。无自助注册、默认管理员或默认密码；账户由获准的本机管理流程创建。

| 方法 | 路径 | 请求／响应 |
|---|---|---|
| POST | `/auth/login` | `{username,password}` → `{user,csrfToken,expiresAt}`，同时设置HttpOnly Cookie |
| GET | `/auth/me` | 当前 `{user:{id,username,role},csrfToken,expiresAt}`，未登录401 |
| POST | `/auth/logout` | 空JSON或无请求体；要求CSRF，返回 `{status:"logged_out"}` 并服务端撤销当前会话 |
| POST | `/auth/password` | `{currentPassword,newPassword}`；新密码12～128字符；返回 `password_changed` 和 `reauthenticationRequired:true` |

- `role` 为 `admin`／`operator`／`viewer`。前两种角色可申请终端，但**仍需目标的逐用户授权**；
  viewer只能读平台及授权目标目录，不能连接、确认或执行终端命令。
- 会话令牌只放 `na_session` Cookie，`Path=/api`、`HttpOnly`、`SameSite=Strict`；
  默认HTTPS且Secure。不要把Cookie令牌或密码放URL、localStorage或前端日志。
- `csrfToken` 可暂存内存；页面刷新先读 `/auth/me` 恢复，再给已认证POST加 `X-CSRF-Token`。
- 登录不发送CSRF头；其他已认证POST都要发送，包括注销、改密、连接、关闭、预览、确认和执行。
  浏览器自行发送Cookie，不从JavaScript读取HttpOnly Cookie，也不改成Bearer令牌登录。
- 登录和其他写请求校验同源Origin／跨站标记。开发继续使用同源代理；没有新增CORS放行。
- 默认空闲30分钟、绝对8小时。`expiresAt`是带Z的绝对期限，不是空闲倒计时；
  到期、注销、停用和改密后重新登录，不自动用旧密码静默重登。
- 连续失败默认按账户5次／来源25次、300秒窗口限流，存入SQLite，重启API不清除窗口。
  这些是项目配置默认，不代表行业统一值。
- `allow_insecure_local_http=True`仅供显式回环开发，且主机名必须为localhost／127.0.0.1／::1。
  正式跨机访问仍需HTTPS；不信任客户端伪造的Forwarded头来改变这个条件。
- 工厂的 `allow_anonymous_reads=True`只用于明确的旧只读回归／兼容场景，默认关闭；
  不允许借此匿名调用终端，不能在正式启用登录时顺手开启。

```ts
export interface AuthSession {
  user: { id: string; username: string; role: "admin" | "operator" | "viewer" };
  csrfToken: string;
  expiresAt: string;
}

export async function postJson<T>(
  path: string, body: unknown, csrfToken?: string, signal?: AbortSignal,
): Promise<T> {
  const response = await fetch(`/api/v1${path}`, {
    method: "POST", credentials: "same-origin", cache: "no-store", signal,
    headers: { Accept: "application/json", "Content-Type": "application/json",
      ...(csrfToken ? { "X-CSRF-Token": csrfToken } : {}) },
    body: JSON.stringify(body),
  });
  const payload: unknown = await response.json().catch(() => null);
  if (!response.ok) {
    const e = payload && typeof payload === "object" ? payload as Partial<ErrorEnvelope> : {};
    throw new ApiFailure(response.status,
      typeof e.code === "string" ? e.code : "http_error",
      typeof e.requestId === "string" ? e.requestId : response.headers.get("X-Request-ID"),
      typeof e.message === "string" ? e.message : `HTTP ${response.status}`,
      Array.isArray(e.fieldErrors) ? e.fieldErrors : []);
  }
  if (payload === null) throw new ApiFailure(response.status, "invalid_json",
    response.headers.get("X-Request-ID"), "响应不是有效的非空JSON");
  return payload as T;
}
// 登录时不传csrfToken；之后使用login/me返回的值。不要在源码中填写真实用户名或密码。
```

### 8.2 终端目标与命令目录

| 方法 | 路径 | 数据／意义 |
|---|---|---|
| GET | `/terminal/vendors` | `{items:[{id,name,platform}],realDeviceVerified:false}`；锐捷／Cisco／华为／H3C |
| GET | `/terminal/targets` | `{items:Target[]}`；仅当前用户被授权的服务端目标；未配置时真实空数组 |
| GET | `/terminal/commands?targetId=...` | 按目标返回命令及是否可执行；也可只传 `vendor` 浏览参考目录 |

`Target`字段为：

| 字段 | 含义 |
|---|---|
| `id,label,address,port` | 独立终端目标编号、人工标签、管理IP及SSH端口 |
| `vendor,platform,version` | 服务器登记的厂商、平台、版本，不是本次自动识别 |
| `compatibilityConfirmed` | **操作者确认**平台／版本适用，不表示本项目已实机认证 |
| `authenticationMethod` | 当前固定 `server_private_key` |
| `hostKeyPolicy` | 当前固定 `strict_known_hosts` |

目标不会向浏览器返回设备账户、私钥路径或known_hosts文件路径。
`targetId`与SNMP的`deviceId`是不同编号，不能按数组位置或IP猜测关联。
资产登记／SNMP成功不会自动授予SSH权限。

命令字段：`id,name,category,risk,modifiesConfiguration,requiresDoubleConfirmation,parameters,
verificationStatus,realDeviceVerified,executable,executionMode,automaticSave`。

- `category`为query/configuration/reference；风险low/normal/high；`parameters`含name/type/required/minimum/maximum。
- 版本、接口、VLAN、MAC、LLDP为查询；描述、端口启停、VLAN创建／删除为受控配置。
- 当前 `verificationStatus:"reference_unverified"`、`realDeviceVerified:false`；
  **厂商目录不是多厂商实机兼容证明**。只有服务端确认目标适用且逐命令启用后，`executable`才为true。
- `executable`只反映目标兼容声明、命令白名单和非reference类别，**不是当前角色最终执行授权**。
  viewer即使读到true也不能操作终端；所有实际操作仍由后端重新检查角色、目标授权和会话归属。
- 重启、保存配置、恢复出厂是reference，不能执行；不自动应答设备的分页、提权或额外确认提示。
- 接口名仅接受字母开头的字母／数字／`/.-`，最长48字符；描述为1～80个ASCII字母数字及 ` _./:-`；
  VLAN为整数1～4094。未知参数、控制字符、换行和原始任意命令拒绝。

### 8.3 连接、预览、确认、执行：四个不同动作

| 方法 | 路径 | 请求／响应 |
|---|---|---|
| POST | `/terminal/sessions` | `{targetId}` → Session；建立SSH，HTTP200仍须看state |
| GET | `/terminal/sessions/{sessionId}` | 读取Session；仅创建它的那一次平台登录可读 |
| POST | `/terminal/sessions/{sessionId}/close` | `{}` → Session；断开通道，不发送设备保存／重启命令 |
| POST | `/terminal/sessions/{sessionId}/operations` | `{commandId,parameters:{...}}` → Operation；**只生成预览，不发给设备** |
| GET | `/terminal/operations/{operationId}` | 读取进度、已返回步骤、最终状态及错误 |
| POST | `/terminal/operations/{operationId}/confirm` | `{firstConfirmed:true,phrase:"我确认执行该操作"}` → `{id,confirmationToken,expiresAt}` |
| POST | `/terminal/operations/{operationId}/execute` | 低／普通风险`{}`；高风险`{confirmationToken}` → Operation |
| GET | `/terminal/sessions/{sessionId}/events?cursor=0&limit=50` | 审计事件，升序；`{items,nextCursor}`，limit1～200 |

调用顺序：
1. 登录，读取targets及目标的命令目录。
2. POST sessions，只有 `state:"ready"` 时提供命令提交能力。
3. POST operations取得服务端命令预览；前端可填入待执行区域，但不能在填入时自动调用execute。
4. 管理员回车／明确确认后才调用execute；高风险先做两次用户确认，再调用confirm取得专用令牌。
5. 每个operation的命令内容冻结。编辑参数／切换设备必须生成新operation，不能复用旧确认。
6. execute请求进行中，可GET同一operation轮询已经持久化的步骤；没有逐按键WebSocket流。
7. 用户退出／取消终端时调用close。断线不自动新建命令、不自动重连重放。

```ts
export interface TerminalSession {
  id: string; targetId: string;
  state: "connecting" | "ready" | "closed" | "failed" | "disconnected" | "interrupted";
  createdAt: string; updatedAt: string; errorCode: string | null;
  mode: "controlled_commands";
}
export interface TerminalOperation {
  id: string; sessionId: string; commandId: string; commands: string[];
  risk: "low" | "normal" | "high";
  state: "prepared" | "confirmed" | "executing" | "completed" | "failed"
    | "partial" | "result_unknown" | "interrupted";
  requiresDoubleConfirmation: boolean;
  expiresAt: string; createdAt: string; updatedAt: string;
  output: string | null;
  steps: { command: string; status: "prompt_returned" | "rejected" }[];
  errorCode: string | null; businessVerified: false; automaticSave: false;
}
```

`prepared`预览默认120秒过期；确认令牌绑定当前用户、平台会话、目标终端和冻结命令，
仅执行时消费一次。重复调用同一operation的execute只返回已有状态，不重新发命令；
前端网络超时后先GET查询，不能生成新operation“自动重试”。

`completed`只表示支持的步骤均读到了CLI提示符且未识别到已知错误，不代表所有厂商错误都能被识别，
更不代表业务验收成功；`businessVerified`保持false。`partial`说明前面步骤可能已经改变配置；
`result_unknown`／`interrupted`说明可能发出过命令，必须核验设备，不能当未执行。
设备额外确认／分页、输出过量、超时、断连、未知提示符均不自动回答或重放。

### 8.4 状态、审计与运行边界

- 每用户最多4个终端，全局16个；单终端串行执行，冲突409。
- 终端空闲300秒关闭；单步超时默认15秒、服务端可配置1～60秒；连接等待有界。
- 单操作输出上限64KiB；32个输出分块有界排队。输出只按文本显示，不作为HTML或完整ANSI终端流执行。
- 连接、准备、确认、发送意图、每个已完成步骤、结束／断连立即事务持久化；
  执行前审计失败不发送，执行后存储失败关闭通道，恢复后保留未知结果。
- 事件字段：`id,action,objectId,occurredAt,details`。命令内容及允许的查询输出有界保存在操作记录；
  不提供任意 `show running-config`、密码命令或完整原始终端录屏。不要在接口描述等普通参数内填写秘密。
- 不承诺通用文本脱敏能识别设备吐出的所有敏感内容；数据库／备份及日志读取权限仍须部署时保护。
- 默认不自动删除历史；保留周期、归档及清理执行器尚未提供，不能把“不删除”描述成已完成合规策略。
- 终端绑定创建它的那一次平台登录；同一用户第二次登录也不能接管第一次的终端。
  注销当前会话立即关闭其通道；停用／改密导致其他会话由后台检查器回收。
- 有终端目标时只支持单API进程，通过OS锁拒绝第二个同库终端运行实例；
  进程重启将未完成命令标记interrupted，不恢复原SSH通道、不自动重放。
- 当前未提供SSH密码认证、Console／USB串口、Telnet、原始按键透传、窗口尺寸同步、任意CLI、自动提权、
  自动保存／回滚、批量下发或可恢复的终端录屏。通用提示符适配及各厂商真实固件仍待现场核验。

### 8.6 后端准备与本机配置：不由浏览器提交设备凭据

1. 使用第0.1节项目内 `setup → init → create-user → doctor → start.cmd` 流程。
   初始化只操作自己的 `.runtime/data/development.sqlite`，不存在时建库／导入获准种子，已有库不覆盖。
   升级已有工作库必须先备份并单独验证迁移，不能把早期作者本机迁移事件当作每个协作者的启动步骤。
2. 账户由 `bootstrap.ps1 create-user yourname --role admin` 建立；密码通过隐藏交互输入。
   高级管理CLI及参数见 [app/auth/cli.py](../app/auth/cli.py)，使用项目内Python并明确自己的数据库。
   不将密码放argv、文档、聊天或Git，不为前端联调启用匿名模式。
3. **推荐项目内启动器显式读取 `.runtime/configs/terminal.local.json`**，
   不是只设置 `INSPECT_TERMINAL_CONFIG` 就能改变该启动器的配置。
   自行集成应用工厂的入口可使用该环境变量／显式参数；不要把两种启动方式混为一谈。
   不向前端开放编辑目标／私钥路径接口。
   格式为 `{targets:[...]}`，每项包含：
   `id,label,address,port,username,private_key,known_hosts,vendor,platform,version,
   compatibility_confirmed,allowed_users,allowed_commands,command_timeout_seconds`。
   目标必须是明确单IP，私钥和known_hosts是现存绝对路径；不接受域名、网段或浏览器任意地址。
   平台组合仅 `ruijie/rgos`、`cisco/ios`、`huawei/vrp`、`h3c/comware`。
   默认不确认兼容、没有授权用户、没有启用命令，因此不会误开放。
4. known_hosts须经可信现场／带外渠道核验；首次指纹采集不等于已获信任，不自动接受未知主机密钥。
   服务账户必须能安全使用私钥且设备支持公钥登录；需要密码认证的设备当前不能冒充已支持。
5. 配置变更需要重建API应用／重启自己的API实例；默认目标为空，前端应正常显示待配置。
   凭据文件和个人配置不上传GitHub；迁移电脑时须重新准备自己的设备授权、路径和主机密钥。
6. 前端完成登录与CSRF对接后再启用对应操作入口；仅有只读客户端时匿名业务查询会遇到401。
   真实设备配置验证另行列明目标、命令及影响，不因代码或文档完成而自动实施。

### 8.7 可复制的调用骨架：不把预览和执行绑成自动链路

下面函数与第3、8.1、8.3节的类型及Fetch函数配套，路径标识符统一编码。
**仅为客户端接入示例，不会在加载时登录、连接或执行命令**；账号密码来自实际用户输入，
目标和命令编号来自实际目录。泛型仍不代替响应的运行时校验。

```ts
export interface TerminalTarget {
  id: string; label: string; address: string; port: number;
  vendor: "ruijie" | "cisco" | "huawei" | "h3c";
  platform: string; version: string; compatibilityConfirmed: boolean;
  authenticationMethod: "server_private_key";
  hostKeyPolicy: "strict_known_hosts";
}
export interface TerminalCommand {
  id: string; name: string; category: "query" | "configuration" | "reference";
  risk: "low" | "normal" | "high"; modifiesConfiguration: boolean;
  requiresDoubleConfirmation: boolean;
  parameters: {
    name: string; type: "interface" | "description" | "vlan"; required: boolean;
    minimum: number | null; maximum: number | null;
  }[];
  verificationStatus: "reference_unverified"; realDeviceVerified: false;
  executable: boolean; executionMode: "privileged_exec" | "user_view";
  automaticSave: false;
}
export interface CommandConfirmation {
  id: string; confirmationToken: string; expiresAt: string;
}

export function loginPlatform(username: string, password: string, signal?: AbortSignal) {
  return postJson<AuthSession>("/auth/login", { username, password }, undefined, signal);
}
export async function restorePlatformSession(signal?: AbortSignal): Promise<AuthSession | null> {
  try { return await readJson<AuthSession>("/auth/me", signal); }
  catch (error) {
    // 只有明确401按未登录处理，断网／503不伪装成未登录或恢复成功。
    if (error instanceof ApiFailure && error.status === 401) return null;
    throw error;
  }
}
export function logoutPlatform(auth: AuthSession, signal?: AbortSignal) {
  return postJson<{ status: "logged_out" }>(
    "/auth/logout", {}, auth.csrfToken, signal);
}
export function changePlatformPassword(
  auth: AuthSession, currentPassword: string, newPassword: string, signal?: AbortSignal,
) {
  return postJson<{ status: "password_changed"; reauthenticationRequired: true }>(
    "/auth/password", { currentPassword, newPassword }, auth.csrfToken, signal);
}
export function listAuthorizedTargets(signal?: AbortSignal) {
  return readJson<{ items: TerminalTarget[] }>("/terminal/targets", signal);
}
export function listTargetCommands(targetId: string, signal?: AbortSignal) {
  const query = new URLSearchParams({ targetId });
  return readJson<{ items: TerminalCommand[] }>(`/terminal/commands?${query}`, signal);
}
export function openControlledTerminal(auth: AuthSession, targetId: string, signal?: AbortSignal) {
  // 返回后必须检查state === "ready"，HTTP200本身不表示SSH连接成功。
  return postJson<TerminalSession>("/terminal/sessions", { targetId }, auth.csrfToken, signal);
}
export function prepareControlledCommand(
  auth: AuthSession, sessionId: string, commandId: string,
  parameters: Record<string, string | number>, signal?: AbortSignal,
) {
  return postJson<TerminalOperation>(
    `/terminal/sessions/${encodeURIComponent(sessionId)}/operations`,
    { commandId, parameters }, auth.csrfToken, signal);
}
export function confirmHighRiskCommand(
  auth: AuthSession, operation: TerminalOperation,
  firstConfirmed: boolean, phrase: string, signal?: AbortSignal,
) {
  // firstConfirmed和phrase必须来自用户真实确认，不能由目录选择／预览回调自动补齐。
  if (!operation.requiresDoubleConfirmation || operation.state !== "prepared")
    throw new Error("当前预览不可申请高风险确认");
  return postJson<CommandConfirmation>(
    `/terminal/operations/${encodeURIComponent(operation.id)}/confirm`,
    { firstConfirmed, phrase }, auth.csrfToken, signal);
}
export function executePreparedCommand(
  auth: AuthSession, operation: TerminalOperation,
  confirmation?: CommandConfirmation, signal?: AbortSignal,
) {
  // 仅在用户明确要求执行时调用。服务端仍会核对期限、状态及令牌，不接受替换commands。
  if (operation.requiresDoubleConfirmation && (!confirmation || confirmation.id !== operation.id))
    throw new Error("缺少与该操作匹配的双确认令牌");
  return postJson<TerminalOperation>(
    `/terminal/operations/${encodeURIComponent(operation.id)}/execute`,
    operation.requiresDoubleConfirmation ? { confirmationToken: confirmation!.confirmationToken } : {},
    auth.csrfToken, signal);
}
export function readControlledOperation(operationId: string, signal?: AbortSignal) {
  return readJson<TerminalOperation>(
    `/terminal/operations/${encodeURIComponent(operationId)}`, signal);
}
export function closeControlledTerminal(auth: AuthSession, sessionId: string, signal?: AbortSignal) {
  return postJson<TerminalSession>(
    `/terminal/sessions/${encodeURIComponent(sessionId)}/close`, {}, auth.csrfToken, signal);
}
```

| 环节 | 接入要求 |
|---|---|
| 页面启动／刷新 | 先 `/auth/me`；401才转未登录。恢复成功后用返回的CSRF，不能沿用上次登录的令牌 |
| 登录／改密／注销 | 密码不持久化；改密成功按 `reauthenticationRequired:true` 清理本地认证及终端操作状态；注销成功后停止轮询。注销请求失败不宣称服务端已经撤销 |
| 授权目录 | 列表为空是合法结果；不自动拿SNMP地址拼装目标。角色仅做客户端预检查，不能取代后端授权 |
| 预览与确认 | 只展示后端冻结的 `commands`；参数或设备变化使本地旧预览／确认失效；高风险的两次用户动作不能合并成自动同意 |
| 确认令牌 | 只留内存，不写URL、持久存储、埋点或日志；执行提交后不复用。确认响应丢失也不能假设令牌仍可再次签发，应查询原operation |
| 执行与恢复 | 先保存operation编号；网络失败、HTTP异常、取消等待后先查询同一operation，不新建操作自动重试，不以“无响应”认定“未发送” |
| 终端退出 | 明确调用close；关页／组件卸载／AbortController都不等价于后端close，更不代表配置已回滚。不要用缺少CSRF的裸sendBeacon冒充可靠关闭 |

### 8.8 事件增量读取与断网处理

事件是审计记录，不是SSH原始输出流；命令文本／已完成步骤从Operation读取。
与通用分页一样，事件游标要求**1～18位十进制数字字符串**；事件读取初始为 `"0"`，仍不要转换成JavaScript Number。
序号来自全局审计，允许不连续；不同session各自维护游标。

```ts
export interface TerminalEvent {
  id: string; action: string; objectId: string; occurredAt: string;
  details: Record<string, unknown>;
}
export async function readTerminalEventBatch(
  sessionId: string, cursor: string = "0", signal?: AbortSignal,
): Promise<{ items: TerminalEvent[]; cursor: string; hasMore: boolean }> {
  const query = new URLSearchParams({ cursor, limit: "50" });
  const page = await readJson<Page<TerminalEvent>>(
    `/terminal/sessions/${encodeURIComponent(sessionId)}/events?${query}`, signal);
  const last = page.items[page.items.length - 1];
  return {
    items: page.items,
    // null只表示当前没有下一页。尾页保留末条id，空页保留旧游标，不能归零。
    cursor: page.nextCursor ?? last?.id ?? cursor,
    hasMore: page.nextCursor !== null,
  };
}
```

- 有下一页时串行读取；无下一页时等下一轮刷新。请求失败保留旧游标，按事件id去重；
  只有消费本页成功后才推进游标，避免丢事件；不要用重置为0“恢复”导致重复追加。
- 一个轮询完成后再安排下一次；离开终端、会话失效或明确停止时取消后续轮询。
  GET session／events并不重置终端300秒空闲期限；看到页面刷新正常不代表SSH永不超时。
- `AbortSignal`／浏览器超时只取消客户端等待，不承诺撤销后端线程或已发送的设备命令。
  execute响应丢失时查询同一operation；`executing`只继续查询，`result_unknown`／`interrupted`
  需核验设备。任何状态都不能触发自动保存、自动回滚或新建operation重放。

### 8.9 前端错误处理矩阵（按HTTP及code区分）

错误文案使用服务端message并保留requestId；不要只按HTTP状态合并所有原因。
未识别的code原样保留，不自行推断成功。下面是处理规则，不代表每条已在正式环境实测。

| HTTP／code | 前端动作／禁止事项 |
|---|---|
| 400 `https_required` | 报告入口或开发条件不符；由后端协调环境，不自动降级传输 |
| 401 `authentication_required` | 清理当前本地认证、CSRF和确认令牌，停止关联轮询；需重新登录，旧终端不能被新登录接管 |
| 401 `invalid_credentials` | 登录时说明凭据错误；改密时也可能表示当前密码错误，不仅凭该code认定旧会话已撤销；可用me核查。不保存密码自动重试 |
| 403 `csrf_rejected` | 重新GET me核对会话及CSRF；不自动重发写请求，尤其execute，先GET原operation核实 |
| 403 `origin_rejected` | 核对同源入口及代理；刷新CSRF、重新登录不能替代修正入口问题 |
| 403 `terminal_permission_denied` | 说明角色禁止终端操作；不尝试前端改role或换接口绕过 |
| 404 `terminal_target_not_found`／`terminal_session_not_found`／`terminal_operation_not_found` | 目标可能未获授权、记录可能不存在或不属于本次登录；不泄露猜测、不自动创建替代操作 |
| 409 `compatibility_not_confirmed`／`command_not_enabled`／`reference_only` | 当前不可执行；由后端获准后处理平台确认／白名单，不在浏览器自行改标志 |
| 409 `operation_expired`／`confirmation_unavailable` | 原预览或确认不可继续；先查询原operation，已执行／执行中不重建；只有确需重新准备时再经用户重新预览、确认 |
| 409 `double_confirmation_required` | 不能执行；核对原操作与用户确认，不自动填入确认文字或替用户签发新确认 |
| 409 `terminal_busy`／`terminal_session_limit`／`terminal_not_ready` | 查询当前会话／操作；等待已有操作或用户关闭多余会话，不自动重连重放 |
| 413 `request_too_large` | 限制提交大小；不能靠分块传输绕过32KiB上限 |
| 422 `validation_error`及领域校验码 | 显示字段错误或整体message；修正参数后重新预览，不以修改前端commands绕过 |
| 429 `login_rate_limited` | 停止自动尝试并提示稍后手动再试；当前未承诺Retry-After响应头，不编造精确解除时间 |
| 501 `configuration_execution_not_implemented` | 功能未实现；不展示成功、不生成执行记录、不自动降级为逐条命令执行 |
| 503 `access_store_unavailable`或其他不可用码 | 保留错误及requestId；执行相关请求先查询原operation，禁止把存储异常当“必定未发送” |
| 网络失败／超时／非JSON／其他HTTP错误 | 保留读取失败状态；GET可有界重试，写请求不自动重试。已有结果只能标为旧结果，不能改观测时间或填充假数据 |
