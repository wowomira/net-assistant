### 脱敏和运行边界

- 导出11张业务表；账号、登录会话、认证限流、访问审计、终端会话/操作、交换机表不导出。
  资产审计属于业务关联历史，按计划保留，不与登录访问审计混淆。
- JSON嵌套字段、JSON字符串和普通文本检查密码、令牌、Cookie、私钥、SNMP community、
  URL用户信息、认证头及常见凭据赋值；清单只记表/列和次数，不记敏感值。
- 本包清单的6次保守剔除均来自主机context里的布尔授权标记`collectionAuthorization`；
  **不是发现或删除了6个密码**。其余真实证据照常保留。原工作库不改写。
- 自动模式识别不等于对任意自由文本做过人工保密审查；设备IP、MAC和网络拓扑仍是真实内网信息。
  因此种子、运行库、清单和采集结果均不公开上传。
- 历史配置快照保留原网段、工具路径等证据，不从它们生成活动配置。
  新环境的扫描/交换机计划默认禁用，监控和SSH目标为空；本次导入也不覆盖已有本地配置。
- 不复制个人环境文件、密钥或驱动。没有带入默认账号，也没有关闭认证。

## 3. 怎样使用与重新制作

在项目根目录执行。当前已有本地`.runtime/venv`，可直接使用项目解释器；这不代表它已经便携。

```powershell
# 只读复核种子
.\.runtime\venv\Scripts\python.exe scripts/workspace.py seed-check

# 本次数据已经导入。这里的init只检查并保留已有运行库，不重复灌入数据
.\.runtime\venv\Scripts\python.exe scripts/workspace.py init

# 自己创建管理员，安全提示中输入密码两次；不要把密码写进命令
.\.runtime\venv\Scripts\python.exe scripts/workspace.py create-user yourname --role admin
.\.runtime\venv\Scripts\python.exe scripts/workspace.py serve
```

启动后本地默认8001端口；登录和同源Cookie流程见根README及后端前端对接说明。
现有工作台没有正式登录页，不要为方便查看数据而开放匿名读取。

### 初始化规则

1. `init`：运行库不存在且种子存在时，验证后预装；没有种子则创建空库。
2. `init`：运行库已存在时只读检查，不覆盖、不合并、不重置。
3. `seed-import --into-empty`：仅用于明确导入到已经存在、结构匹配且所有业务/认证/会话表完全为空的库。
   只要已有一条业务或账号、会话、审计、限流记录，就拒绝导入。
4. 新目标在同卷临时库中验证，通过后无覆盖原子发布；现有空库则在写事务内再次检查，
   一次性导入并验证，失败回滚。导入前后不会出现部分业务表已经启用的中间状态。
   数据库和截图安装共用一个操作系统文件锁，防止并发初始化时一方失败清理另一方引用的截图。
5. 截图仅处理成功探测引用的32位十六进制PNG文件名；源缺失或名字非法时记录缺失，
   不更改原探测成功/失败状态来掩盖问题。已有同名不同内容的目标文件拒绝覆盖。

本次已执行过一次`seed-import --into-empty`，不要对已填充的运行库重复导入。
