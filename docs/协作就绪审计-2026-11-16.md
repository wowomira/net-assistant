# 网维助手 0.10.0：GitHub 协作与可运行性审计

**日期：2026-11-16（北京时间）。对象：最后一次讨论的后端 0.10.0，而非早期压缩包或旧运行服务。**

## 1. 一句话结论和边界

本轮把“只有作者机器上的源码、依赖、工作库和旧服务才能凑起来”的状态，
整理为**朋友可以按根 README 重建依赖、初始化自己的空库、创建自己的账号并进行同源后端联调的源码仓库**。

保留最终版业务边界：登录、角色、CSRF、受控 SSH 是后端已实现能力；
现有前端仍是阶段性只读页面，没有正式登录页、改密页或终端交互。
不以放开匿名访问、赠送默认密码、伪造设备数据或提供任意 SSH 命令来让演示“看起来能跑”。

以下三件事不能混为一谈：

1. **源码协作可运行**：新建隔离环境、独立库、后台关闭，可通过账号读取和联调。
2. **旧工作服务正式升级**：旧工作库六处结构差异、真实账号、服务重启切换仍是独立任务。
3. **成品部署**：正式前端、HTTPS、设备接入、权限配置和真实交换机验收尚未全部完成。

## 2. 初始问题及本轮处理

| 等级 | 原状态／风险 | 本轮处理 | 仍需知道的边界 |
|---|---|---|---|
| 阻塞 | `.git` 从外层移入 project，但历史索引仍包含外层资料和旧 `project/` 前缀；当前文件大量显示删除+未跟踪 | 按真正仓库根 `project` 组织提交，保留历史，不做强推或改写历史 | 当前树移除外层文件不等于删除其历史，仓库继续私有 |
| 阻塞 | 旧根 README 声称把依赖、运行数据、本机配置全量上传，不能作为朋友安装流程 | 改成明确的源码协作范围和运行说明，提供 `.gitignore` | 原始本机文件留在磁盘，不物理删除 |
| 阻塞 | API 默认要求认证，但原 uvicorn 入口在 HTTP 下不允许登录；前端没有登录页 | 提供显式回环 HTTP 开发入口，保留认证；用 `/docs` 登录后同源读取 `/console/` | 是后端联调入口，不是正式产品登录页；正式需 HTTPS |
| 阻塞 | API 是只读查询入口，不会自动创建数据库，新机直接启动会缺库 | `init` 显式创建独立空开发库，账号单独交互创建 | 无默认账号和示例资产；空台账不是出错 |
| 高 | 已知旧工作库虽标 0006，却有六处主键 NOT NULL 差异 | 新 `check`/`serve` 只读检查 revision、完整性、外键及这六处字段，异常就拒绝 | 没有修复旧工作库，没有覆盖旧备份，没有声称旧 API 上线 |
| 高 | 旧后台可自动读取共用源码的新迁移，测试误触工作库 | 新入口固定 `.runtime` 独立库和计划；清除子进程继承的 `INSPECT_*`；所有计划默认关闭 | 没有修改旧后台自动迁移实现，今后仍应独立 clone 开发 |
| 高 | 原配置写死作者 Nmap 的 E 盘位置、实验网地址和工作数据库绝对路径 | 生成仅回环的本机配置，相对路径随仓库定位，Nmap 默认从 PATH 查找 | 实网地址、驱动/权限和设备授权由各人独立配置 |
| 高 | `.venv`、node_modules、工具缓存、数据库和报告混在源码旁，体积大且可能泄露本机信息 | 忽略运行态和密钥，提交锁定依赖及示例；新环境在 `.runtime` 重建 | 不把“复制旧 Python exe”当作新机安装 |
| 高 | 前端 API 类型生成仍指向 0.6.0 | 改为 0.10.0 并实际重新生成类型，保留原 UI | 类型生成成功不等于已实现新业务页面 |
| 中 | 只有历史自动测试数字，缺本轮重装和真实 HTTP 证据 | 新建全依赖环境；新增安全/路径测试与迁移目录的真实 HTTP 测试 | 不是第二台物理电脑或新 Windows 虚拟机 |
| 中 | 缺少团队协作/CI/安全说明 | 新增 CONTRIBUTING、SECURITY、Windows CI 和本报告 | 云端 CI 状态单独核验，不因存在配置就计通过 |
| 中 | 多个 README 仍为历史版本和绝对路径 | 顶部明确根 README 优先、旧内容是历史；当前入口无作者机器路径要求 | 为保留历史没有批量重写所有旧验收记录 |

## 3. 最终版各部分能做什么、还差什么

| 部分 | 当前可用内容 | 合作方还需要接的内容／实测边界 |
|---|---|---|
| 平台认证 | 用户口令哈希、登录限流、可注销 Cookie 会话、角色、CSRF、改密和停用后失效 | 正式登录/改密/过期 UI，账号运维流程、HTTPS |
| 只读工作台 | 资产、扫描、证据、调度、交换机查询；本轮契约对齐 | 没有注册/登录按钮，开发期先在相同浏览器用 `/docs` 登录；不宣称最终 UI 完成 |
| 数据库 | SQLAlchemy/Alembic，新开发库从当前迁移创建；查询不迁移 | 旧工作库偏差专门修复，定期备份/恢复演练、留存清理 |
| 发现与台账 | Nmap 适配、授权范围、证据、稳定资产与关联、历史查询 | 新朋友须装 Nmap 并配置自己的真实授权范围，不能复制作者实验网当默认目标 |
| 本机采集 | Windows 网卡、地址、接口、邻居的只读快照与历史 | Windows 原生采集非跨平台能力；邻居缓存不证明设备在线 |
| Gatus 监控 | 独立 SQLite、受控计划、健康读取与托管代码 | 自行安装/构建工具、登记监控目标，默认空计划不运行 |
| 交换机只读采集 | SNMPv3 authPriv 协议、标准接口/FDB/LLDP 等、周期线程和持久化 | 实机型号/固件、管理范围、只读账号与服务环境凭据；协议测试不替代真实锐捷验收 |
| 受控 SSH | 严格 known_hosts、服务器密钥、逐用户目标授权、模板、预览、确认、执行与审计 | 没有密码式 SSH、串口、任意命令透传或真实交换机成功登录/下发验收证据 |
| 一键配置 | 契约和失败边界存在，真实空目录/404/501 | 没有实际模板内容和执行器，不属于已完成能力 |
| 部署与协作 | 根目录脚本、独立构建/库、文档、依赖锁、Windows CI | 不是离线成品包；生产代理、运维、真实设备上线仍需后续任务 |

## 4. 目录约定及为什么这么放

```text
project/
  README.md                    唯一当前协作入口
  CONTRIBUTING.md / SECURITY.md 协作与安全
  scripts/workspace.py         不依赖当前终端路径推算仓库位置
  tests/                      独立启动安全与真实HTTP验证
  .github/workflows/verify.yml Windows干净环境验证
  docs/                       本报告及工具说明
  net-assistant/backend/      原最终版后端，不再额外套 project 前缀
  net-assistant/frontend/     正式源码，不在运行副本上开发
  net-assistant/docs/         原实施记录
  .runtime/                   每个人独有，不提交
    venv/                     新建Python环境，不动原 .venv
    frontend/                 npm依赖与构建副本，不替换现有 dist
    data/development.sqlite   新空开发库，不借旧工作库
    configs/                  自己的扫描、调度、监控、SNMP、SSH配置
```

与“直接移动所有 exe/venv 后上传”相比，这样可以区分源码、系统依赖、运行配置和业务数据，
明确哪个部分属于每个协作者，且不会把作者的本地路径和口令变成团队依赖。
真正工具获取和七类运行组件逐项见 `工具与运行环境.md`；
本轮没有擅自重打包 Windows/Edge/Nmap 等系统或第三方目录，也没有宣称再分发许可已核验。

## 5. 可复现启动与验收

在根目录，依序运行：

```powershell
python scripts/workspace.py doctor
python scripts/workspace.py setup --index-url https://pypi.org/simple
python scripts/workspace.py init
python scripts/workspace.py create-user yourname --role admin
python scripts/workspace.py check
python scripts/workspace.py serve
```

`setup` 使用锁定的基础、开发、mDNS、SNMP 与 Playwright 依赖，`npm ci` 从 package-lock 安装。
当前支持/验证 Python 3.13 x64 和 Node 24，不承诺随意更换版本仍兼容。
先在同浏览器 `/docs` 的登录接口登录，再打开同源 `/console/`；不要从旧 API 8000 的页面读新版 8001。
页面空数据是新库的预期结果。停止开发服务用 Ctrl+C，只影响本次进程，不停旧 Windows 服务。

新入口特意没有 `--host` 参数，不自动安装驱动/服务、打开防火墙或接入公网。
默认不发起实网扫描，不写入已授权旧实验网的数据，不安装 Agent。

## 7. 发布和协作前的剩余任务

1. **朋友先按 README 独立运行**：安装 Python/Node，创建自己的账号，不索取作者工作库和密钥。
2. **前端认证/终端接入**：不是本轮重做 UI；按0.10.0对接说明继续，保持预览/确认/执行的安全边界。
3. **旧生产环境专门修复**：先一致性备份，校正早期0006，处理自动迁移入口，协调服务切换，不直接恢复旧备份丢掉新数据。
4. **真实设备授权与兼容验收**：型号、固件、管理地址、只读SNMPv3、SSH密钥和known_hosts、用户目标权限，逐项配置。
5. **生产上线**：HTTPS、可信代理、账户恢复、日志/备份/留存、故障与回滚、真实重启验证。
6. **团队权限**：有朋友GitHub账号后再邀请；仓库继续私有，未擅自改公开/添加成员。
7. **若要离线成品包**：单独设计可分发运行时、许可证/哈希、离线依赖与第二台干净Windows验证，本轮不冒充完成。
